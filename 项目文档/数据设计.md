# 数据设计

> 2026-09-13 审核：本文存在实现与合同不同步，具体见[开发进度审核报告 S08／S11](开发进度审核报告.md)。下方设计约束不代表代码已实现；后续修复须补齐 P2 状态动作及 P3／P4 数据、接口合同，不得以当前缺陷反向放宽计划书。

用途：按开发规范第五节，在首个相关模块迁移前记录字段、约束、索引与保留规则；按模块逐段增量维护。已落地结构以 [backend 迁移](../基于Vue3的多组织活动管理系统_zcode/backend/src/main/resources/db/migration/)为准并同步说明。概念 ER 图不作为物理表依据。

通用约定：

- 表与列名 snake_case；标识内部为 BIGINT UNSIGNED，接口层一律以字符串传输（开发规范 2.2）。
- 时间点统一 UTC（连接时区 UTC），列类型 TIMESTAMP(6)；纯日期（费用发生日期等）后续模块用 DATE。
- 金额表在对应模块建表时以 DECIMAL(12,2) 起步（人民币），容量在该模块迁移前定稿。
- 状态枚举以 VARCHAR 存储、UPPER_SNAKE_CASE；不使用 MySQL ENUM，便于迁移扩展。
- 已应用迁移不回写；演示重置仅针对独立测试库。

## 账号模块（M01，P1.1）

### account 账号（全局登录身份）

| 列 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| id | BIGINT UNSIGNED | PK AUTO_INCREMENT | 内部主键 |
| username | VARCHAR(32) | NOT NULL，UNIQUE（utf8mb4_0900_ai_ci，大小写不敏感唯一） | 格式校验 `^[a-zA-Z0-9_]{3,32}$` |
| password_hash | VARCHAR(255) | NOT NULL | BCrypt 散列；不存明文，不进日志 |
| status | VARCHAR(16) | NOT NULL DEFAULT 'ACTIVE' | 首期仅 ACTIVE；预留 DISABLED |
| auth_version | BIGINT | NOT NULL DEFAULT 1 | 修改密码、恢复成功时 +1；会话绑定版本，旧会话失效 |
| created_at | TIMESTAMP(6) | NOT NULL DEFAULT CURRENT_TIMESTAMP(6) | |
| updated_at | TIMESTAMP(6) | NOT NULL DEFAULT CURRENT_TIMESTAMP(6) ON UPDATE CURRENT_TIMESTAMP(6) | |

索引：`uk_account_username (username)`。
保留规则：账号不物理删除（历史署名、审计与报名记录需要）；注销能力首期不建设。

### recovery_credential 恢复凭据（一次性恢复码）

| 列 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| id | BIGINT UNSIGNED | PK AUTO_INCREMENT | |
| account_id | BIGINT UNSIGNED | NOT NULL，FK→account(id) | |
| code_hash | CHAR(64) | NOT NULL | 明文恢复码规范化后的 SHA-256 十六进制；明文仅在发放响应中出现一次，不落库 |
| status | VARCHAR(16) | NOT NULL | ACTIVE / CONSUMED / REVOKED |
| active_flag | TINYINT UNSIGNED | GENERATED ALWAYS AS (CASE WHEN status='ACTIVE' THEN 1 ELSE NULL END) STORED | 与 account_id 组成唯一约束，保证每账号至多一条 ACTIVE |
| issued_at | TIMESTAMP(6) | NOT NULL DEFAULT CURRENT_TIMESTAMP(6) | |
| consumed_at | TIMESTAMP(6) | NULL | 使用时间；使用后不可复用 |

索引：`uk_recovery_active (account_id, active_flag)`、`idx_recovery_account_status (account_id, status)`。
有效期：在使用、重新签发（REVOKED）或账号失效前有效，不设时间过期（后端架构 4.1）。
发放与消费并发：消费以 `UPDATE ... WHERE status='ACTIVE'` 影响行数判定，重复消费统一失败。

### audit_log 关键操作审计

| 列 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| id | BIGINT UNSIGNED | PK AUTO_INCREMENT | |
| actor_account_id | BIGINT UNSIGNED | NULL，操作时未登录（如注册者本人即操作者则填） | 语义为"谁做的"，随模块扩展 |
| scope | VARCHAR(32) | NOT NULL | 如 ACCOUNT |
| action | VARCHAR(64) | NOT NULL | UPPER_SNAKE_CASE，如 ACCOUNT_REGISTERED |
| target | VARCHAR(128) | NOT NULL | 如 `account:123` |
| reason | VARCHAR(512) | NULL | 操作原因（取消、驳回等场景使用） |

索引：`idx_audit_scope_target (scope, target)`、`idx_audit_actor_created (actor_account_id, created_at)`。
规则：关键业务变更同事务写入，失败则变更回滚；历史不可编辑删除（开发规范第三节）。运行日志与审计分离，运行日志不重复保存审计内容。

### organization_member 组织成员关系

| 列 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| id | BIGINT UNSIGNED | PK AUTO_INCREMENT | |
| org_id | BIGINT UNSIGNED | NOT NULL，FK→organization(id) | |
| account_id | BIGINT UNSIGNED | NOT NULL，FK→account(id) | |
| role | VARCHAR(16) | NOT NULL | OWNER（组织负责人）/ MEMBER（普通成员）；不建设通用角色编辑器 |
| status | VARCHAR(16) | NOT NULL DEFAULT 'ACTIVE' | ACTIVE / LEFT / REMOVED；LEFT／REMOVED 为历史状态，重新加入复用主关系行 |
| joined_at | TIMESTAMP(6) | NOT NULL DEFAULT CURRENT_TIMESTAMP(6) | 首次加入时间 |
| created_at / updated_at | TIMESTAMP(6) | 同账号表约定 | updated_at 兼作被移除时间的判定基准 |

索引与约束：
- `uk_member_active (org_id, account_id, active_flag)`，其中 `active_flag` 为生成列（status='ACTIVE' 时为 1，否则 NULL）——同一账号在同一组织至多一条有效成员关系（计划书第九节）。
- `idx_member_account (account_id, status)`——本人组织目录查询。

**主关系复用模型（审核 R05 已修复）：** 退出（LEFT）或移除（REMOVED）不产生新行，而是将原行置为相应状态；凭有效邀请重新加入时**更新原行**为 ACTIVE／MEMBER，`memberId` 全生命周期稳定，可作为后续活动职责、任务与历史署名的外键基线。历史过程（加入、退出、移除、重新加入）以 audit_log 记录。被移除成员只能凭**移除之后创建**的邀请重新加入（以邀请 `created_at` 晚于成员行 `updated_at` 判定），移除前发出的邀请对其失效；自行退出成员可凭任何有效邀请重新加入。V5 迁移已把历史重复行收敛为单条主关系。

并发与锁（后端架构 5.1，审核 R01/R04 已修复）：组织创建为纯 INSERT 无需锁；成员与负责人变更、退出、移除、邀请接受与创建／撤销均取组织行排他锁（`SELECT ... FOR UPDATE`），**锁内重读当前状态并重验身份**；连接隔离级别统一 READ COMMITTED（Hikari `transaction-isolation`），并有真实 MySQL 并发测试覆盖（同账号重复接受、不同账号争抢末次、并发撤销负责人、撤权与创建竞争）。成员变更的跨业务职责联动随 P2—P6 接入，届时按后端架构提升为 application 的 MembershipWorkflowService，当前阶段保留在 organization 模块内实现。

### organization_invitation 组织邀请

| 列 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| id | BIGINT UNSIGNED | PK AUTO_INCREMENT | |
| org_id | BIGINT UNSIGNED | NOT NULL，FK→organization(id) | |
| code_hash | CHAR(64) | NOT NULL | 邀请码明文规范化后的 SHA-256；明文仅创建响应返回一次，供分享 |
| created_by | BIGINT UNSIGNED | NOT NULL，FK→account(id) | 创建邀请的负责人 |
| expires_at | TIMESTAMP(6) | NOT NULL | 有效期截止；创建时给定（1～30 天） |
| max_uses | INT UNSIGNED | NOT NULL | 最大使用次数（1～100） |
| used_count | INT UNSIGNED | NOT NULL DEFAULT 0 | 已接受次数；扣减在组织排他锁内完成 |
| status | VARCHAR(16) | NOT NULL DEFAULT 'ACTIVE' | ACTIVE / REVOKED |
| created_at | TIMESTAMP(6) | NOT NULL DEFAULT CURRENT_TIMESTAMP(6) | |

索引：`idx_invitation_org_status (org_id, status)`。
有效性判定：status='ACTIVE' 且未过期且 used_count < max_uses；三者任一不满足统一按"邀请无效"处理，不区分原因。

## 活动模块（M02，P2.1 起）

### activity 活动

| 列 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| id | BIGINT UNSIGNED | PK AUTO_INCREMENT | |
| org_id | BIGINT UNSIGNED | NOT NULL，FK→organization(id) | 活动归属组织，全部读写带组织范围 |
| name | VARCHAR(128) | NOT NULL | 活动主题，1～128 字符 |
| description | VARCHAR(2000) | NULL | 活动简介 |
| owner_member_id | BIGINT UNSIGNED | NOT NULL，FK→organization_member(id) | 活动负责人；必须是本组织 ACTIVE 成员的当前主关系行（主关系复用后 id 稳定） |
| status | VARCHAR(16) | NOT NULL DEFAULT 'DRAFT' | P2.1 仅 DRAFT；后续阶段扩展 PENDING_APPROVAL／APPROVED／…（计划书 5.1 主流程） |
| version | BIGINT | NOT NULL DEFAULT 1 | V12（S08）：编辑冲突用整数版本，每次成功写入 +1；请求携带期望版本时做条件更新 |
| start_time / end_time | TIMESTAMP(6) | NULL | 草稿允许不完整；提交前校验 end > start |
| location | VARCHAR(255) | NULL | 活动地点 |
| budget | DECIMAL(12,2) | NOT NULL DEFAULT 0.00 | 人民币预算，允许零、禁止负数（CHECK 约束）；容量上限与模块接口定稿一致 |
| registration_scope | VARCHAR(16) | NOT NULL DEFAULT 'INTERNAL' | INTERNAL / PUBLIC；已有报名后禁止切换（P2.3） |
| capacity | INT UNSIGNED | NULL | 正整数名额；草稿可空 |
| registration_start / registration_end | TIMESTAMP(6) | NULL | 报名窗口；reg_start < reg_end 且 reg_end ≤ start（字段齐备时校验） |
| registration_open | TINYINT(1) | NOT NULL DEFAULT 0 | V10（S02）：独立报名开关，只约束新申请；新建与重新确认后默认关闭，撤回已确认活动复位为关闭；仅组织负责人或活动负责人可变 |
| proposal | LONGTEXT | NULL | V7：活动方案文稿，草稿期由组织负责人或活动负责人维护 |
| review_note / submitted_by / confirmed_by / confirm_type | VARCHAR(500)／BIGINT／BIGINT／VARCHAR(16) | NULL，前两者 FK→account(id) | V7：单级确认留痕；confirm_type 为 SELF／OTHER；处理历史与原因走 audit_log |
| confirmed_at | TIMESTAMP(6) | NULL | V11（S07）：最近一次立项确认时间；撤回草稿保留，`DRAFT` 且非空表示调整期待确认（任务／物资只读、不得按初始草稿删除） |
| created_by | BIGINT UNSIGNED | NOT NULL，FK→account(id) | 创建人（组织负责人） |
| created_at / updated_at | TIMESTAMP(6) | 同账号表约定 | |

索引：`idx_activity_org_status (org_id, status)`、`idx_activity_owner (owner_member_id)`。
CHECK：`budget >= 0`、`capacity IS NULL OR capacity > 0`。
规则：草稿不对外发布；未发布（DRAFT／PENDING_APPROVAL）仅组织负责人与被指定的活动负责人可见，列表与子资源使用同一可见性（S06，`Activity.isVisibleTo`）；删除仅限未确认且无依赖的草稿（S07 的“曾确认后撤回仍可删除”尚未修复）；方案文稿存于 activity.proposal（V7），不预建独立表。

并发与锁：活动创建与草稿编辑按后端架构 5.1 取组织行**共享锁**校验当前有效成员资格与操作者角色。
V12（S08）起落实共同锁协议：活动下子记录写入取活动行共享锁（`FOR SHARE`），活动自身写入与跨子记录写路径（报名审核／取消、报名开关、撤回确认）取活动行排他锁（`FOR UPDATE`），顺序统一为 组织 → 活动 → 子记录；报名审核在活动行锁内重读活动状态与报名记录后再校验名额。
创建防重：`request_key` 记录创建活动的 `Idempotency-Key`，`(org_id, request_key)` 唯一约束兜底并发重放。
附件（S09／S10）：`purpose` 区分用途（`ACTIVITY_DOC` 或 `TASK_ATTACHMENT`）；`task_id` 仅在任务资料时非空，附件只能关联活动或任务之一（后端架构 6.1）。文件名由服务端随机生成，原文件名只作为展示元数据；存储目录下的 `tmp/` 为受控暂存区，校验通过后才移入持久目录。

## 执行、复盘与归档模块（M02 后半程、M07、M08，P6 起）

### activity 状态与留痕字段（V17 起）

## AI 文本辅助（M11、M12，P8 起，V19）

### ai_config 组织模型配置（每组织一条）
