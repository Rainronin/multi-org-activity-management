# 数据设计

用途：按开发规范第五节，在首个相关模块迁移前记录字段、约束、索引与保留规则；按模块逐段增量维护。已落地结构以 [backend 迁移](../基于Vue3的多组织活动管理系统_zcode/backend/src/main/resources/db/migration/)为准并同步说明。概念 ER 图不作为物理表依据。

通用约定：

- 表与列名 snake_case；标识内部为 BIGINT UNSIGNED，接口层一律以字符串传输（开发规范 2.2）。
- 时间点统一 UTC（连接时区 UTC），列类型 TIMESTAMP(6)；纯日期（费用发生日期等）后续模块用 DATE。
- 金额表在对应模块建表时以 DECIMAL(12,2) 起步（人民币），容量在该模块迁移前定稿。
- 状态枚举以 VARCHAR 存储、UPPER_SNAKE_CASE；不使用 MySQL ENUM，便于迁移扩展。
- 已应用迁移不回写；演示重置仅针对独立测试库。

## 账号模块（M01，P1.1）

### account 账号（全局登录身份）

| 列 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| id | BIGINT UNSIGNED | PK AUTO_INCREMENT | 内部主键 |
| username | VARCHAR(32) | NOT NULL，UNIQUE（utf8mb4_0900_ai_ci，大小写不敏感唯一） | 格式校验 `^[a-zA-Z0-9_]{3,32}$` |
| password_hash | VARCHAR(255) | NOT NULL | BCrypt 散列；不存明文，不进日志 |
| status | VARCHAR(16) | NOT NULL DEFAULT 'ACTIVE' | 首期仅 ACTIVE；预留 DISABLED |
| auth_version | BIGINT | NOT NULL DEFAULT 1 | 修改密码、恢复成功时 +1；会话绑定版本，旧会话失效 |
| created_at | TIMESTAMP(6) | NOT NULL DEFAULT CURRENT_TIMESTAMP(6) | |
| updated_at | TIMESTAMP(6) | NOT NULL DEFAULT CURRENT_TIMESTAMP(6) ON UPDATE CURRENT_TIMESTAMP(6) | |

索引：`uk_account_username (username)`。
保留规则：账号不物理删除（历史署名、审计与报名记录需要）；注销能力首期不建设。

### recovery_credential 恢复凭据（一次性恢复码）

| 列 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| id | BIGINT UNSIGNED | PK AUTO_INCREMENT | |
| account_id | BIGINT UNSIGNED | NOT NULL，FK→account(id) | |
| code_hash | CHAR(64) | NOT NULL | 明文恢复码规范化后的 SHA-256 十六进制；明文仅在发放响应中出现一次，不落库 |
| status | VARCHAR(16) | NOT NULL | ACTIVE / CONSUMED / REVOKED |
| active_flag | TINYINT UNSIGNED | GENERATED ALWAYS AS (CASE WHEN status='ACTIVE' THEN 1 ELSE NULL END) STORED | 与 account_id 组成唯一约束，保证每账号至多一条 ACTIVE |
| issued_at | TIMESTAMP(6) | NOT NULL DEFAULT CURRENT_TIMESTAMP(6) | |
| consumed_at | TIMESTAMP(6) | NULL | 使用时间；使用后不可复用 |

索引：`uk_recovery_active (account_id, active_flag)`、`idx_recovery_account_status (account_id, status)`。
有效期：在使用、重新签发（REVOKED）或账号失效前有效，不设时间过期（后端架构 4.1）。
发放与消费并发：消费以 `UPDATE ... WHERE status='ACTIVE'` 影响行数判定，重复消费统一失败。

### audit_log 关键操作审计

| 列 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| id | BIGINT UNSIGNED | PK AUTO_INCREMENT | |
| actor_account_id | BIGINT UNSIGNED | NULL，操作时未登录（如注册者本人即操作者则填） | 语义为"谁做的"，随模块扩展 |
| scope | VARCHAR(32) | NOT NULL | 如 ACCOUNT |
| action | VARCHAR(64) | NOT NULL | UPPER_SNAKE_CASE，如 ACCOUNT_REGISTERED |
| target | VARCHAR(128) | NOT NULL | 如 `account:123` |
| reason | VARCHAR(512) | NULL | 操作原因（取消、驳回等场景使用） |
| detail | JSON | NULL | 非敏感结构化补充；不存凭据、恢复码明文 |
| created_at | TIMESTAMP(6) | NOT NULL DEFAULT CURRENT_TIMESTAMP(6) | |

索引：`idx_audit_scope_target (scope, target)`、`idx_audit_actor_created (actor_account_id, created_at)`。
规则：关键业务变更同事务写入，失败则变更回滚；历史不可编辑删除（开发规范第三节）。运行日志与审计分离，运行日志不重复保存审计内容。

## 组织模块（M01，P1.2 起）

### organization 组织

| 列 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| id | BIGINT UNSIGNED | PK AUTO_INCREMENT | |
| name | VARCHAR(64) | NOT NULL | 1～64 字符，创建时 trim；不强制全局唯一（同一系统可有同名组织） |
| description | VARCHAR(512) | NULL | 组织简介，可空 |
| status | VARCHAR(16) | NOT NULL DEFAULT 'ACTIVE' | 首期仅 ACTIVE；预留 DISABLED |
| created_at / updated_at | TIMESTAMP(6) | 同账号表约定 | |

索引：主键即可（组织名不唯一、按 id 关联）。
保留规则：组织不物理删除；解散能力首期不建设。

### organization_member 组织成员关系

| 列 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| id | BIGINT UNSIGNED | PK AUTO_INCREMENT | |
| org_id | BIGINT UNSIGNED | NOT NULL，FK→organization(id) | |
| account_id | BIGINT UNSIGNED | NOT NULL，FK→account(id) | |
| role | VARCHAR(16) | NOT NULL | OWNER（组织负责人）/ MEMBER（普通成员）；不建设通用角色编辑器 |
| status | VARCHAR(16) | NOT NULL DEFAULT 'ACTIVE' | ACTIVE / LEFT / REMOVED，P1.3 已使用；重新入组主关系待按审核 R05 修复 |
| joined_at | TIMESTAMP(6) | NOT NULL DEFAULT CURRENT_TIMESTAMP(6) | 首次加入时间 |
| created_at / updated_at | TIMESTAMP(6) | 同账号表约定 | |

索引与约束：
- `uk_member_active (org_id, account_id, active_flag)`，其中 `active_flag` 为生成列（status='ACTIVE' 时为 1，否则 NULL）——同一账号在同一组织至多一条有效成员关系（计划书第九节）。
- `idx_member_account (account_id, status)`——本人组织目录查询。
- 当前实现重新入组时新增成员行，与后端架构要求的稳定主关系不符。须按[审核 R05](开发进度审核报告.md)新增迁移修复并保留历史；修复前不将当前结构作为活动外键设计的最终基线。

并发与锁（后端架构 5.1）：组织创建为纯 INSERT 无需锁；成员与负责人变更、退出、移除、邀请接受取组织行排他锁（`SELECT ... FOR UPDATE`）。成员变更的跨业务职责联动随 P2—P6 接入，届时按后端架构提升为 application 的 MembershipWorkflowService，当前阶段保留在 organization 模块内实现。

### organization_invitation 组织邀请

| 列 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| id | BIGINT UNSIGNED | PK AUTO_INCREMENT | |
| org_id | BIGINT UNSIGNED | NOT NULL，FK→organization(id) | |
| code_hash | CHAR(64) | NOT NULL | 邀请码明文规范化后的 SHA-256；明文仅创建响应返回一次，供分享 |
| created_by | BIGINT UNSIGNED | NOT NULL，FK→account(id) | 创建邀请的负责人 |
| expires_at | TIMESTAMP(6) | NOT NULL | 有效期截止；创建时给定（1～30 天） |
| max_uses | INT UNSIGNED | NOT NULL | 最大使用次数（1～100） |
| used_count | INT UNSIGNED | NOT NULL DEFAULT 0 | 已接受次数；扣减在组织排他锁内完成 |
| status | VARCHAR(16) | NOT NULL DEFAULT 'ACTIVE' | ACTIVE / REVOKED |
| created_at | TIMESTAMP(6) | NOT NULL DEFAULT CURRENT_TIMESTAMP(6) | |

索引：`idx_invitation_org_status (org_id, status)`。
有效性判定：status='ACTIVE' 且未过期且 used_count < max_uses；三者任一不满足统一按"邀请无效"处理，不区分原因。
