## 二、从源码与配置示例重建

```powershell
# 1. 数据库与账号（生产按最小权限授予该库）
CREATE DATABASE activity_prod CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci;
GRANT ALL PRIVILEGES ON activity_prod.* TO 'activity'@'<主机>' IDENTIFIED BY '<强密码>';

# 2. 后端配置：复制示例后填写，凭据文件不进仓库
Copy-Item .\基于Vue3的多组织活动管理系统_zcode\backend\src\main\resources\application-local.example.yml `
          .\基于Vue3的多组织活动管理系统_zcode\backend\config\application-local.yml
#   spring.datasource.* 指向目标库；app.ai.master-key 填部署侧主密钥（Base64 的 32 字节 AES 密钥）

# 3. 迁移与启动（启动即执行 Flyway，V1→V19 全部迁移）
cd .\基于Vue3的多组织活动管理系统_zcode\backend
.\mvnw.cmd spring-boot:run "-Dspring-boot.run.profiles=local"

# 4. 前端构建（产物为静态文件，交给反向代理）
cd ..\frontend; npm ci; npm run build     # 输出 dist/
```

迁移文件共 19 个（`backend/src/main/resources/db/migration/V1__baseline.sql` … `V19__ai_config_generation.sql`），全部为增量且幂等登记在 `flyway_schema_history`；**不要**对已有库手工改表，结构变更一律新增迁移文件。

**本机实测（2026-09-13，空库重建）：** 创建空库 `activity_p9_build` 后启动应用，Flyway 依次应用 V1→V19，`flyway_schema_history` 最新版本 19 且 `success=1`，库内共 19 张表（18 张业务／基础表 + `flyway_schema_history`），`GET /api/health` 返回 `{"status":"UP","database":"UP"}`。

## 三、附件、备份与恢复

**附件目录：** `app.upload.dir`（默认 `./uploads`，相对后端工作目录）。生产必须指向持久磁盘或挂载卷，并把该目录纳入备份范围；数据库只保存登记与元数据，文件本身在磁盘上，两者要配套。

```powershell
# 备份（维护窗口内执行：先暂停写入，等待在途上传与模型调用结束）
& '<MySQL>\bin\mysqldump.exe' -h 127.0.0.1 -u root -p --single-transaction --routines --triggers `
  --set-gtid-purged=OFF --default-character-set=utf8mb4 activity_prod > D:\backup\activity_prod.sql
Copy-Item -Recurse -Force .\backend\uploads D:\backup\uploads
# 恢复（独立环境，先建空库）
& '<MySQL>\bin\mysql.exe' -h 127.0.0.1 -u root -p --default-character-set=utf8mb4 activity_restore < D:\backup\activity_prod.sql
Copy-Item -Recurse -Force D:\backup\uploads .\backend\uploads
# 用恢复库启动一个实例，核对记录与文件
.\mvnw.cmd spring-boot:run "-Dspring-boot.run.jvmArguments=-Dspring.datasource.url=jdbc:mysql://127.0.0.1:3306/activity_restore?... -Dserver.port=8099"
```

**本机实测（2026-09-13）：**

| 步骤 | 结果 |
| --- | --- |
| 数据库导出 | `activity_test` 导出 25.7MB（`--single-transaction --routines --triggers`） |
| 附件目录备份 | 运行时持久目录 `backend/uploads` 共 34 个文件全部复制 |
| 恢复 | 导入独立库 `activity_p9_restore`：19 张表；活动 3604、报名 1086、支出 219、附件登记 538、AI 生成记录 489、反馈 29；`flyway_schema_history` 最新版本 19 |
| 关联核对 | 备份的 34 个附件文件与恢复库中的登记行**一一对应** |
| 可读取性 | 用恢复库启动实例（端口 8099）：`/api/health` UP、`/api/public/activities` 返回 119 条公开活动，说明恢复后记录可正常读取 |

**必须记录的一条运行时说明：** 该测试库同时被自动化测试使用，而测试按 R08 把上传目录指向临时目录并在进程退出后清理，因此 538 条附件登记中有 504 条指向已清理的临时文件，只有 34 条属于运行时持久目录。**生产备份的完整性判断只能以运行时持久目录为准**；核对方法：

```sql
-- 导出全部 stored_name，与上传目录文件清单比对，缺文件的行即为不一致
SELECT stored_name FROM attachment;
```

## 四、生产构建与反向代理

前端是标准 SPA（Vue Router history 模式），反向代理必须把未知路径回退到 `index.html`，并把 `/api` 转发到后端；后端只需 8080 一个端口。**本机实测（`node .\生成脚本\audit_p9_build.mjs`）**：用最小静态服务器（未知路径回退 `index.html`、`/api` 反向代理到 8080）提供 `dist/`，`/` 与 `/org/1/activities/1` 均返回应用入口且引用哈希资源（`/assets/index-*.js`，`text/javascript`），浏览器打开嵌套路由被守卫重定向到登录页并正常渲染表单，深链接 `/public/activities/1` 渲染公开列表，`/api/health` 经代理返回 UP，页面错误 0。

会话与安全相关：生产必须用 HTTPS，并把 `server.servlet.session.cookie.secure` 置为 `true`（开发环境为 false）；CSRF 由 Spring Security 的会话令牌提供，前端写请求自动携带。

## 五、AI 模型接入（可选功能）

AI 是可选亮点，未配置、停用或不可用时方案与总结仍可手工完成。生产部署需要：

| 参数 | 来源 | 建议 |
| --- | --- | --- |
| `app.ai.enabled` | 环境变量 `ACTIVITY_AI_ENABLED` | 需要 AI 时 true；否则 false（入口返回 503 `AI_DISABLED`） |
| `app.ai.master-key` | 环境变量 `ACTIVITY_AI_MASTER_KEY`，Base64 的 32 字节 AES 密钥 | **必须由部署侧保管**，不进库不进仓库；轮换时同时改 `master-key-id` 并让组织重新录入密钥 |
| `app.ai.allowed-hosts` | 环境变量 `ACTIVITY_AI_ALLOWED_HOSTS` | 只列实际使用的模型域名（支持 `*.example.com`）；新增可信网关时扩充 |
| `app.ai.allow-private-hosts` | 环境变量 | **生产必须 false**；true 只允许本机桩服务验证使用 |
| `app.ai.max-concurrent-calls` / `max-calls-per-day-per-org` | 环境变量 | 按模型服务额度设置；当日额度按持久生成记录统计（含连接测试） |
| 组织级配置 | 界面「组织设置 → AI 模型」 | 协议、完整端点、模型 ID、密钥、输出上限字段与上限、时限；保存→测试→启用 |

出口限制：除应用内的域名白名单与公网地址校验外，部署侧应限制出网目标（只允许已登记模型域名），应用不声称一次 DNS 检查即可替代受限出口。测试连接只发送固定短文本，仍会消耗少量额度。

## 六、已知限制

1. **真实厂商模型未接入**：本机验收用桩模型服务核对协议与编排，真实模型的文本质量、厂商限流与计费额度未实测；接入后需按[验收复核记录](验收复核记录.md)第二节第 1 条补齐证据。
2. **性能结论限于单机开发环境**：`audit_p9_flow.mjs` 记录的常规读写 5～35ms、模型连接测试 52ms 均为单机单请求观测值，未做并发压测；并发正确性由名额、金额与锁的用例保证，不因性能目标调整而降低。
3. **注册与登录限流为首期进程内实现**：单实例部署下有效；多实例部署需要外部限流（未纳入本期）。
4. **站内提示只有站内渠道**：投递即意图行本身，不部署外部渠道与投递队列重试（已记录为最小例外）。
