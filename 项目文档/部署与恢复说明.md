## 一、环境要求

### 运行日志（2026-10-04实际配置）

后端标准输出与文件同时输出，文件默认后端工作目录下`./logs/activity.log`，可用`ACTIVITY_LOG_FILE`指定持久绝对路径，部署账号需可写。复用Boot／Logback按日期及大小轮转，默认单文件阈值10MB、历史14天、压缩归档总量200MB、启动清理历史；归档名`activity.log.yyyy-MM-dd.i.gz`。200MB针对归档，当前活跃文件另计，大小轮转与清理异步，不能当作严格实时文件系统配额。日志目录已忽略Git；部署备份和磁盘监控按实际路径维护。

请求日志含时间、级别、服务端requestId、路由模板、方法、毫秒耗时、HTTP状态和code。安全未映射路径用UNMAPPED，认证入口仅固定路径；不记录正文／参数／Cookie／凭据。正常INFO，已处理错误／安全拒绝WARN，未预期异常ERROR；堆栈保留类型与位置，丢弃原始异常消息和suppressed，原因环去重。DEBUG默认关闭。业务审计仍在数据库同事务，关联及前后状态覆盖与实际限制见当前审核。

本机实测：完整168项verify及新构建activity_test/V25真实HTTP40项、12个可解压gzip通过；仅该验证进程使用`--logging.logback.rollingpolicy.max-file-size=1KB`快速触发轮转，正式10MB配置未改。未实等14天或填满200MB、未做生产长期容量验收，500及链外异常仅测试专用探针验证。证据和重复命令见[脚本索引](../生成脚本/README.md)及审核报告。

## 三、附件、备份与恢复

**附件目录：** `app.upload.dir`（默认 `./uploads`，相对后端工作目录）。生产必须指向持久磁盘或挂载卷，并把该目录纳入备份范围；数据库只保存登记与元数据，文件本身在磁盘上，两者要配套。

维护窗口先暂停业务写入，等待在途上传和模型调用结束。以下模板从工作区根目录执行，`$backupPath` 必须是本次新建的备份目录；使用客户端文件输出避免 PowerShell 重定向改变 SQL 编码。

```powershell
$mysqlBin = 'C:/Program Files/MySQL/MySQL Server 8.4/bin'
$mysqlHost = '127.0.0.1'
$mysqlPort = 3306 # 替换为实际源实例端口，不沿用历史临时端口。
$backupPath = 'D:/backup/activity-prod-本次备份'
$uploadPath = Join-Path (Get-Location) '基于Vue3的多组织活动管理系统_zcode/backend/uploads'
# 若 app.upload.dir 已自定义，先把 uploadPath 改为其实际绝对路径。
New-Item -ItemType Directory -Path $backupPath -ErrorAction Stop | Out-Null
& "$mysqlBin/mysqldump.exe" -h $mysqlHost -P $mysqlPort -u root -p --single-transaction --routines --triggers --set-gtid-purged=OFF --default-character-set=utf8mb4 "--result-file=$backupPath/activity_prod.sql" activity_prod
if ($LASTEXITCODE -ne 0) { throw '数据库导出失败，本次备份不可用。' }
Copy-Item -LiteralPath $uploadPath -Destination (Join-Path $backupPath 'uploads') -Recurse -ErrorAction Stop
```

恢复到独立空库及新附件目录，勿覆盖运行环境。先在目标MySQL实例创建尚不存在的 `activity_restore`（不使用IF NOT EXISTS绕过空库检查），并明确目标主机与端口；不得导入activity_dev或现有正式库。恢复端口可与备份源不同，凭据按恢复实例填写。使用客户端 `source` 命令导入（PowerShell不支持 `<` 输入重定向）：

```powershell
$restoreHost = '127.0.0.1'
$restorePort = 13306 # 独立恢复实例的实际端口，运行前确认。
& "$mysqlBin/mysql.exe" -h $restoreHost -P $restorePort -u root -p --default-character-set=utf8mb4 activity_restore "--execute=source $backupPath/activity_prod.sql"
if ($LASTEXITCODE -ne 0) { throw '数据库恢复失败，停止后续启动。' }
$restoreUploadPath = 'D:/restore/activity-uploads-本次恢复'
if (Test-Path -LiteralPath $restoreUploadPath) { throw '恢复目录已存在，请选择新的空目录。' }
Copy-Item -LiteralPath (Join-Path $backupPath 'uploads') -Destination $restoreUploadPath -Recurse -ErrorAction Stop
```

用独立配置将 `spring.datasource.url` 指向恢复库、`app.upload.dir` 指向恢复附件目录、`server.port` 指向空闲端口后启动。AI 密文恢复还需要对应的主密钥及 keyId，由部署侧安全保管，不能只备份数据库便宣称模型配置可恢复。核对业务记录、全部有效附件引用及真实下载，再恢复写入。

恢复时先选与备份schema兼容的应用版本；直接启动最新JAR会自动应用后续迁移，不再是原版本恢复证明。记录应用提交／迁移版本、数据库导出与附件清单的哈希、导入退出码、有效附件核对及真实读取结果。ZIP完整性和备份文件存在只证明文件可读，不能代替这组恢复检查；需要回退时按V25限制配套恢复应用／库／附件与主密钥。

## 五、AI 模型接入（可选功能）

AI 是可选亮点，未配置、停用或不可用时方案与总结仍可手工完成。本机与生产均需部署主加密密钥；它用于加密组织填入的厂商API Key，两者不能混用。已有数据库配置也必须补齐，不能认为测试进程曾成功便说明正式运行环境已配置。

本机将一次生成的Base64主密钥写入已忽略的 `backend/config/application-local.yml` 的 `app.ai.master-key`，同时保留稳定的 `master-key-id`（默认 `local-v1`）。生成方式见 `backend/src/main/resources/application-local.example.yml`，只生成一次并安全保管；不要覆盖已有数据库配置、重复添加YAML键，或在每次启动时生成新值。已有加密数据时先恢复与数据库配套的原主密钥，不能直接换随机值。环境变量配置也须由部署环境稳定提供，终端临时设置会在新会话消失。

修改后重启后端，在「组织设置 → AI 模型」填写厂商参数与API Key，保存成功即启用，然后到活动方案／复盘生成文稿；测试连接是可选诊断，保存不调用厂商。旧停用配置需由负责人重新保存或恢复启用，不批量迁移启用。`503 AI_KEY_UNAVAILABLE` 若说明主密钥缺失／格式错误，先由管理员修正部署配置并重启；反复改填组织API Key不能解决。若密文无法解密，则核对主密钥与数据是否匹配，恢复原密钥或重新录入组织配置。

| `app.ai.enabled` | 环境变量 `ACTIVITY_AI_ENABLED` | 需要 AI 时 true；否则 false（入口返回 503 `AI_DISABLED`） |
| `app.ai.master-key` | 环境变量 `ACTIVITY_AI_MASTER_KEY`，Base64 的 32 字节 AES 密钥 | **必须由部署侧保管**，不进库不进仓库；轮换时同时改 `master-key-id` 并让组织重新录入密钥 |
| `app.ai.allowed-hosts` | 环境变量 `ACTIVITY_AI_ALLOWED_HOSTS` | 只列实际使用的模型域名（支持 `*.example.com`）；新增可信网关时扩充 |
| `app.ai.allow-private-hosts` | 环境变量 | **生产必须 false**；true 只允许本机桩服务验证使用 |
| `app.ai.max-concurrent-calls` / `max-calls-per-day-per-org` | 环境变量 | 按模型服务额度设置；当日额度按持久生成记录统计（含连接测试） |
| 组织级配置 | 界面「组织设置 → AI 模型」 | 协议、完整端点、模型 ID、密钥、输出上限字段与上限、时限；保存即生效，测试可选 |

出口限制：除应用内的域名白名单与公网地址校验外，部署侧应限制出网目标（只允许已登记模型域名），应用不声称一次 DNS 检查即可替代受限出口。测试连接只发送固定短文本，仍会消耗少量额度。
