## 验证与易错点

- 正式业务目录为 `基于Vue3的多组织活动管理系统_zcode/frontend` 和 `backend`，根目录一套 Git 仓库，不迁移、不重新初始化。
- 后端运行命令以 README 为准，PowerShell 用 `.\mvnw.cmd verify` 并确认退出码；不要把异常退出一概解释为管道问题。测试基类强制 activity_test，但浏览器／API 服务需单独显式覆盖并核对真实数据源。
- 本轮[新增复核脚本](../生成脚本/audit_ds_progress.mjs)使用无组织账号；原 audit_p4_ui.mjs 先让参与者入组，不能代表外部公开参与全链路。观察脚本退出 0 也不代表所有输出合格。
- 本轮真实详情页五档宽度无页面级溢出，但未做五档全部交互、短屏及 200% 缩放，不能写成手机验收通过。
- 现有任务／物资锁前 Context、附件两阶段间旧 Task 对象不能算锁内当前授权；修改时追踪全部调用，不只修单个入口。
- 撤回保留报名，不会“清空报名记录”；调整期状态包括撤回草稿与重新提交待确认。已有报名者的结果与调整提示应独立于内部草稿权限。
- 公开活动外部报名不建立成员关系；“我的报名”必须指向活动并提供合法结果／取消路径，不能只显示报名人的姓名。
- 通知界面／投递可随 P7，当前业务来源意图必须现在记录。不得修改规范来适应缺陷。
- 本地配置不入库不打包，脚本不输出凭据；新增数据只用于测试库，保留用户既有数据。不要运行历史一次性补丁或全文件回滚有效改动。

本轮仅同步文档和新增审核脚本，未改业务源码／迁移，未提交推送。完成状态仍以功能开发清单为唯一依据。
