## 运行与验证注意

- Windows 优先 PowerShell；在业务 `backend/` 执行 `.\mvnw.cmd verify`，在 `frontend/` 执行 README 中的 npm 检查。`mvnw.cmd` 经 `Tee-Object` 管道会返回退出码 1，以日志中的 `BUILD SUCCESS` 为准。
- 本地后端配置在 `backend/config/application-local.yml`（连 `activity_dev`，不入库、不打进 JAR）；测试配置由 `ActivityTestBase` 强制连接 `activity_test`。**端到端复核必须显式覆盖数据源**：`.\mvnw.cmd spring-boot:run "-Dspring-boot.run.profiles=local" "-Dspring-boot.run.jvmArguments=-Dspring.datasource.url=jdbc:mysql://127.0.0.1:3306/activity_test?..."`，并核对启动日志里的 `Database: jdbc:mysql://127.0.0.1:3306/activity_test`。
- 注册限流按来源 IP 计数（10 次／5 分钟）。测试基类 `FlowTestSupport` 已为每个测试账号分配独立 IP；外部脚本重复跑注册流程会撞 429，必要时重启后端清空内存窗口。
- `audit_p234_recheck.mjs` 需要 `AUDIT_TEST_DATABASE=activity_test`；其时间边界构造用 `mysql.exe -u root`（本机回环空密码）直接改 `start_time`，因为合法路径必须撤回草稿、会清空报名记录。
- 登录／退出会使 CSRF 缓存失效，后续写请求重取；成员与会话状态需要迟到响应隔离。
- Element Plus 采用显式导入；类型／编译通过不能替代浏览器运行验证。桌面与手机分别检查真实 viewport 和溢出。
- UI 观察脚本（`生成脚本/audit_s10_ui.mjs`）：登录按钮文案是「进入工作区」，输入用 placeholder 定位（Element Plus 表单标签不是 `label for`），登录后落点由路由守卫决定，等待条件写成“离开 /login”。
- Hikari 隔离级别值为 `TRANSACTION_READ_COMMITTED`；文件路径先绝对化和规范化，再校验所属目录。不要把注释所称锁或补偿当成实际实现。
- 统一 token、优先现有组件与框架、按当前单侧栏 Demo 开发；不换模板、不加签到／OCR、不擅自扩大业务。

结束一次任务时更新事实所属文档和本摘要入口，记录实测／未测范围；不要因上下文或额度中断把“已写代码”升级为“验收完成”。
