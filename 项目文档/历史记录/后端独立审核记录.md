## 4. 运行时确认的缺陷

| 编号 | 严重性 | 结论 | 证据（本轮实测） |
| --- | --- | --- | --- |
| ACT-01 | 必修 | 活动**归档后仍可 PATCH 改写**关键字段，绕过 `reopen` 且不留 `reopen_reason`／`reopen_count` | 归档（状态 ARCHIVED）后 `PATCH /activities/{id}` 返回 **200**，`name` 被改写，`version` 9 → 10；取消态同样 200 |
| AUTH-02 | 必修 | **归档后物资仍可改写**：物资编辑与状态流转都放行 | 归档活动（ARCHIVED）上：物资状态流转 → **200**；带正确版本编辑 → **200**，实测名称改为"归档后改名成功"、数量 3 → **77**、版本 3。任务编辑返回 409 `TASK_STATE_CONFLICT`（任务链有守卫），**物资链没有** |
| AUTH-03 | 必修 | **费用票据可被普通成员下载**：凭证列表已按管理者拦截，同一 `canManage` 未用于下载 | 同一凭证：负责人列表 200、**普通成员列表 404**、**普通成员下载 200（12 字节）**；被测活动的负责人为组织负责人、普通成员无管理权（已核对 `ownerMemberId=1` vs 成员 mid=2） |
| CONC-01 | 必修 | 反馈并发提交撞唯一键未兜底 → **500**（数据未损坏，但第二个请求拿不到幂等结果） | 两会话并发提交同一账号反馈：一个 **200**、一个 **500 `INTERNAL_ERROR`**，库内仍为 1 条；服务端日志 `DuplicateKeyException: Duplicate entry '5-1' for key 'feedback.uk_feedback_activity_account'`。串行重复提交（双击场景）返回 200，仅并发路径暴露 |
| AI-01 | 必修 | AI 生成并发同 `Idempotency-Key` 撞唯一键未兜底 → **500** | 用本地桩模型（`allow-private-hosts=true`）并发两次同键生成：一个 **500 `INTERNAL_ERROR`**、一个 201 `SUCCEEDED`；日志 `DuplicateKeyException: Duplicate entry '1-1-audit-ai-concurrent-…' for key 'ai_generation.uk_ai_generation_request'`，最终只落 1 条记录 |
| SEC-01 | 必修 | 恢复接口限流键取自查询参数，**可被 `?username=` 绕过**，且键无界增长 | 固定键第 11 次 → **429**；每次换 `?username=kN` 连续 6 次 → **全部 401**（无一次 429） |
| SEC-08 | 建议 | 畸形路径变量落 `Exception` 兜底 → **500** 而非 400 | `attachments/abc/download` 与 20 位超长 id 均 **500 INTERNAL_ERROR**；日志为 `MethodArgumentTypeMismatchException`，全局无该异常处理器 |
| SEC-12 | 观察 | 匿名 `GET /api/auth/csrf` 即创建会话 | 响应 `Set-Cookie: JSESSIONID` |

### 同一根因的三个落点（唯一键未兜底）

`CONC-01`（feedback）、`AI-01`（ai_generation）与活动／附件／经费的既有兜底写法形成对照：活动（`ActivityService`）、经费（`ExpenseService`）、附件（`AttachmentService`）都捕获 `DuplicateKeyException` 并按已提交结果恢复，**feedback 与 ai_generation 两处漏了**。表现为并发同键请求中一个成功、另一个 500，数据无损坏但客户端拿不到幂等结果。

### 静态确认、尚未运行时复现

| 编号 | 严重性 | 位置 | 说明 |
| --- | --- | --- | --- |
| AI-02 | 条件性必修 | `AiEndpointPolicy` | `allow-private-hosts=true` 时四道 SSRF 校验同时失效且无留痕；默认 false 不可利用。本轮为复现 AI-01 临时开启过该开关，验证了"开启后确实可指向回环地址"这一前提 |
| SEC-03／AUTH-08 | 建议 | `AuthVersionFilter`、`AccessMapper.selectStatusById` | 每请求只核对 `auth_version`，`selectStatusById` 是死代码；账号停用后既有会话不失效（当前无停用入口） |
| AUTH-05 | 建议 | `ExpenseService`、`AttachmentService`、V12／V15／V16 | 幂等键唯一范围为组织级且**不含账号维度**（`activity`／`attachment`／`expense` 三者皆是；`ai_generation`／`feedback`／`registration` 含账号或资源维度）→ 同组织另一活动同键同内容重放会 201 返回**别的活动**的记录 |

## 5. 被实测证伪／不成立的静态结论

审查过程中有 5 条静态推断**不成立**，不得据此要求修改：

| 静态推断 | 实测结果 |
| --- | --- |
| 分页 `page=Integer.MAX_VALUE` 整数溢出 → 500 | **200**（page 1／100000／2147483647 均正常，空 items） |
| `pageSize` 无上界可被放大 | `pageSize=101` → **400 VALIDATION_FAILED**（`@Max` 生效） |
| 全站缺少 `X-Content-Type-Options: nosniff` | 下载与普通响应均返回 **`nosniff: nosniff`** 与 **`X-Frame-Options: DENY`**、`Cache-Control: no-store` |
| 报名名额存在 check-then-act 并发竞态 | 复核确认在"组织 → 活动"排他锁内完成，原子；既有并发用例断言恰好 1 条通过 |
| 附件路径穿越与存储型 XSS 可达 | 不可达（UUID 存储名 + 扩展名／Content-Type／魔数三重校验 + 强制 `attachment` + 无静态映射） |

**结论**：子代理的静态结论在未经运行时验证前不能直接采信；本轮的必修项均已区分"实测确认"与"待验证"。

## 6. 已核查无问题的重点项

- **跨组织与跨身份越权**：身份只来自会话，`orgId` 从不作为授权依据，96 个端点逐条核对**无"只校验登录、不校验归属"的端点**；成员管理无自我提权路径，最后一名负责人有保护。
- **活动负责人边界**：统一比对 `actor.memberId == activity.owner_member_id`，无法管理同组织其他活动（AUTH-01／02／03 属状态与资源归属边界，不是角色边界的越权）。
- **乐观锁与幂等**：活动／任务／费用的版本前置条件与条件更新齐备，冲突 409，无静默覆盖。
- **金额与时间**：`DECIMAL(12,2)` + Java `BigDecimal` + SQL 聚合，时间为 `TIMESTAMP(6)` 且连接串 UTC。
- **公开端点**：字段白名单 + 未发布一律 404，既有测试逐字段断言；`registration` 表无内部备注列。
- **归档只读的其余路径**：附件、经费、执行记录、反馈均拒绝写入（仅 PATCH 与任务／物资漏网）。
- **AI 密钥保护**：AES-GCM + 随机 nonce、仅存密文、查询只回 `hasApiKey`；主密钥缺失为失败关闭（无明文降级）。
- **前端**：`v-html`／`innerHTML` 零命中；请求客户端统一 ProblemDetail、超时与取消保护完整覆盖响应体读取；会话代次机制使 401 并发只触发一次登录引导。
