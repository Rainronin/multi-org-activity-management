### 5. P1.1 账号与会话（M01 第一部分）

**数据与接口合同（首次建立）：** [数据设计](../数据设计.md)与[接口说明](../接口说明.md)按开发规范第五节创建，登记账号模块三表（account、recovery_credential、audit_log）与八个 auth 端点的字段、错误码与前端消费约定。

**后端：**

- V2 迁移：account（BCrypt 散列、auth_version）、recovery_credential（生成列 `active_flag` + 唯一约束保证每账号至多一条 ACTIVE）、audit_log（同事务审计）。
- 注册返回一次性恢复码（安全随机 128 位、分段展示、仅存 SHA-256 摘要）；重名 409 `USERNAME_TAKEN` 带字段错误。
- 登录走 Spring Security 表单过滤器：成功 204（绑定 auth_version 入会话）、失败 401 `AUTH_INVALID_CREDENTIALS` 统一提示（不泄露账号存在性）；CSRF 对匿名登录不豁免。
- 恢复：同一事务改密、旧码 CONSUMED（UPDATE 影响行数防并发双花）、发放新码、auth_version+1；旧码重放统一 401。重签需验证当前密码；改密版本 +1 使旧会话 401（当前会话换绑）。
- 限流：进程内固定窗口——登录按账号+IP 失败计数（成功清零）、恢复/注册按尝试计数，429 + `Retry-After`。
- 新增 security 包：AccessMapper（只读）、AccountUserDetails、AuthVersionFilter（逐请求核对版本）、AuthRateLimitFilter、ProblemResponses。

**前端：**

- 建立路由（懒加载页面 + 登录引导守卫，next 仅接受站内相对路径）与会话 store：CSRF 凭据单飞获取与作废重取、`observeUnauthorized` 401 单飞（仅已登录状态切换，迟到 401 不清除新登录）。
- AuthLayout 左右分屏按 [LoginPreview](../../UI演示/src/LoginPreview.vue) 还原（品牌区、大标题层级、表单排版）；Demo 玻璃备注卡为虚构活动数据，按 UI 规范未迁移。
- 登录／注册／恢复／账号四页：失焦校验 + 提交整表校验、失败保留输入、错误按码区分提示；恢复码仅展示一次（RecoveryCodeDialog 要求确认已保存）。

**验证：** `mvnw test` 16 项通过；真实链路经 5174 代理：注册→CSRF 登录 204→me→退出→401、错误密码 401、无 CSRF 403、恢复换密、重签；**后端重启后旧账号登录 204**（P0.1"重启持久化"待补闭环）。headless Chrome 渲染桌面 1440 与设备模拟 390：`scrollWidth == clientWidth`，无横向溢出。

**经验记录：**

- 登录成功会轮换 CSRF token（Spring Security CsrfAuthenticationStrategy）——前端会话层必须在登录／退出后作废缓存的 CSRF 凭据并重取，已实现。
- headless Chrome 的 `--window-size` 在 Windows 125% DPI 下实际视口为 1.25 倍（390 → 489），截图会裁切右侧造成"横向溢出"假象；判断溢出必须用 CDP `Emulation.setDeviceMetricsOverride` 并核对 `scrollWidth == clientWidth`。

**待补：** 未登录公开浏览与外部参与路径随 P4.1；401 并发单飞的浏览器级联测随 P4.1 登录回跳；组织能力随 P1.2。

### 22. S08 编辑冲突、共同锁协议与创建防重（未提交）

**编辑冲突（乐观锁）：** 活动 PATCH、任务改派（`updateAssignment`）、物资更新（`update`）在携带期望 `version` 时做条件更新；影响行数为 0 时活动侧区分「版本冲突」与「状态变化」，返回 409 `EDIT_CONFLICT` 并给出当前版本，不再静默覆盖。版本在状态流转、方案保存、报名开关、确认等写路径统一 +1（`markConfirmed` 与 `transitionStatus` 归入同一次流转，避免重复递增）。未携带版本时按旧客户端兼容处理，合同已在接口说明标注。

**共同锁协议：** 新增 `lockActivityShared`（`FOR SHARE`）与 `lockActivity`（`FOR UPDATE`）。任务与物资的创建／编辑／状态流转在组织行锁后取活动行共享锁；活动自身写入取排他锁；报名审核／驳回／管理取消与本人取消改为「组织锁 → 活动锁 → 锁内重读活动状态与报名记录 → 名额校验 → 状态更新」，修掉架构评审指出的“锁前读活动状态”。

**创建防重：** `POST /activities` 必须携带 `Idempotency-Key`；服务端先查 `request_key`，同键同内容返回原资源（仍校验当前身份与可见性），同键异内容 409 `IDEMPOTENCY_KEY_REUSED`，缺键 400 `IDEMPOTENCY_KEY_REQUIRED`。权限判断放在防重键校验之前，避免未授权调用者借错误码探测约定；比较前按落库规则补齐默认值（预算 0.00、范围 INTERNAL），否则重放会被误判为内容不同。数据库唯一约束是并发重放的最后一道保证。

**回归测试：** 新增 `EditConflictTest` 4 项（活动旧版本保存被拒与版本递增、状态动作同样递增版本、任务与物资旧版本被拒、按请求键幂等）。对照实验：关闭活动与任务的版本条件、物资版本入参后，失败点与预期一致；还原后 62 项通过。防重侧即使关掉服务端查询也会被唯一约束挡成 500，说明有数据库层兜底。

- **权限按计划书 7.4**：登记与查看限组织负责人或本活动负责人（其他成员与外部账号 404）；确认／驳回／作废仅组织负责人，活动负责人非组织负责人返回 403（区分“看不到”与“看得到但不能确认”）。
- **锁协议**：登记与提交取组织共享锁 → 活动共享锁；确认与作废取组织共享锁 → **活动行排他锁**，并在锁内求当前有效已确认合计后再判断超支（后端架构 5.3）。
- **超支**：合计超出活动预算时必须由组织负责人填写超支说明后仍允许确认，余额允许为负；状态守卫保证重复确认不重复累计。
- **无票规则**：提交时若既没有已登记凭证也没有无票说明，返回 400 并指向 `noReceiptNote`（服务端不识别票据内容）。
- **版本与防重**：编辑、提交、确认、驳回、作废都必带 `version`（缺失 400、过期 409）；创建与更正登记必带 `Idempotency-Key`，写入不可变指纹，同键同内容重放返回原记录、同键异内容 409。

### 38. P8 AI 文本辅助后端（M11、M12）

**数据（V19）：** 新建 `ai_config`（每组织一套当前模型配置：协议、完整端点、模型 ID、AES-GCM 密文与 keyId、输出上限字段与上限、时限、启用状态、`connection_revision`／`tested_revision`、操作者与 `version`）与 `ai_generation`（生成记录：防重键与内容指纹、输入来源摘要与范围说明、在途配置快照、输出正文、错误码、请求标识、人工采用状态）。表中没有任何存放密钥的列。

**配置与密钥（`modules/ai`）：** `AiKeyCipher` 用标准 AES-GCM 加密密钥，随机 nonce、认证标签与 keyId 一并保存，组织 ID 作为关联数据；主密钥由部署环境提供（`ACTIVITY_AI_MASTER_KEY`，Base64 的 32 字节），缺失或无法解密只让 AI 配置返回 503 `AI_KEY_UNAVAILABLE`，不影响手工业务。`AiEndpointPolicy` 在保存与每次调用前校验：只允许 HTTPS、部署域名清单（支持通配）与 443 端口，禁止 userinfo／片段／携带凭据的 query，重新解析域名并拒绝回环、私网、链路本地与云元数据地址；客户端关闭重定向。`AiCallGate` 提供部署开关、组织 5 分钟频率、组织当日额度（按持久生成记录统计，含连接测试）与单实例并发门控。

**端点：** 配置读取／保存／测试／启用／停用／清除密钥、输入范围预览、生成、按类型列最近记录、记录详情与人工采用（详见接口说明第七节）。

**验证：** 新增 `AiEndpointPolicyTest` 4 项（http／缺主机、userinfo／片段／凭据 query、清单与私网地址、非 443 端口）、`AiConfigFlowTest` 4 项（密钥加密保存且不回显、版本与修订合同、测试与启用先后、非负责人只读）、`AiGenerationFlowTest` 8 项（OpenAI 与 Anthropic 调用形态、防重键重放、失败与超时、调用期间配置变化、撤权后不可读、额度耗尽、诱导文字定界、矛盾资料原样送出）。后端 **119 项测试 BUILD SUCCESS**（较上阶段 103 项新增 16 项）。
