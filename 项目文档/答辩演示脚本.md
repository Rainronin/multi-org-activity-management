# 答辩演示脚本

用途：给出一次 15～20 分钟演示的固定路线、逐步操作与要说明的要点，并附常见提问的回答依据。演示只使用真实流程与真实数据，不播放录屏、不读固定模板；未配置模型时走手工编写路径，不假装 AI 可用。

准备：后端 `.\mvnw.cmd spring-boot:run "-Dspring-boot.run.profiles=local"`（127.0.0.1:8080，连测试库 `activity_test`），前端 `npm run dev`（http://127.0.0.1:5174）。浏览器准备四个窗口：组织负责人、第二负责人、活动负责人（普通成员）、外部参与者（手机视口 390×844）。

## 一、开场（1 分钟）

一句话定位：**面向多组织场景的活动管理系统**——账号可加入多个组织、组织之间数据隔离、活动从方案立项到归档复盘全流程留痕，另有两项可控的 AI 文本辅助。

要展示的三条主线，后面每一幕都落到其中之一：**权限与状态机**、**并发与一致性（名额／金额／版本）**、**真实数据可复算**。

## 二、演示路线

### 第 1 幕 账号、组织与角色（2 分钟）

1. 注册第一个账号 → 创建组织 → 侧栏出现「组织概览／活动管理／我的任务／成员管理／组织设置」。
2. 邀请第二个账号，接受邀请；把第二个账号提升为**组织负责人**（多负责人审核要用）。
3. 说明要点：同一账号可加入多个组织，身份按组织分别生效；组织之间数据完全隔离（后面第 8 幕用跨组织访问验证）。

### 第 2 幕 方案立项与审批（3 分钟）

1. 组织负责人创建活动（名称、负责人=普通成员、时间、地点、名额、预算），进入**草稿**。
2. 切到活动负责人（普通成员）窗口：填写方案 → **提交确认**。
3. 切回组织负责人：**驳回**并填写原因（"缺少经费预算说明"）→ 活动回到草稿、驳回原因留档 → 修改方案重提。
4. 切到第二负责人：**确认立项**（他人审核，界面不会把自行确认伪装成他人审核）。
5. 说明要点：确认后关键内容不能直接改，需先**撤回确认**再改再确认（现场改一次时间演示 409 → 撤回 → 改 → 重新确认）。

### 第 3 幕 任务、物资与附件（2 分钟）

1. 组织负责人分派任务给普通成员；成员在「我的任务」看到并推进到完成。
2. 维护物资清单（名称、数量、单位、负责人、状态），说明**物资状态不随任务状态自动变化**。
3. 上传活动资料（允许的类型/大小），演示一次超大文件被拒绝（413 `ATTACHMENT_TOO_LARGE`）与伪装类型被拒绝（400）。
4. 用普通成员窗口尝试修改他人任务与维护物资 → 403，说明权限按矩阵收敛。

### 第 4 幕 报名：内部与公开（3 分钟）

1. 内部活动开启报名，成员报名 → 负责人审核通过（名额与待审计数在工作台可见）。
2. 公开活动：手机视口打开公开列表 → 活动详情（**不显示预算、方案与成员**）→ 登录 → 报名 → 「我的报名」查结果 → 在允许时间内取消 → 重新申请。
3. 说明要点：公开参与不产生组织成员身份；取消只释放一次名额；同账号不重复建主记录；最后名额不会超发（并发审批只允许一个成功）。

### 第 5 幕 经费（2 分钟）

1. 活动负责人登记支出（金额、日期、分类、经手说明）→ 提交（**没有凭证必须写无票说明**，现场先漏填一次看 400）。
2. 组织负责人**确认**（已确认支出与余额实时变化）；演示超预算确认时必须填写说明（409 `EXPENSE_OVER_BUDGET`）。
3. 作废一笔已确认支出，再用「更正登记」建立关联新记录并重新确认 → 统计只计一次。
4. 说明要点：金额用十进制字符串传输与存储，两位小数不丢精度；重复确认不会重复累计。

### 第 6 幕 执行、反馈与复盘（2 分钟）

1. 启动执行（**仍有待审报名时被 409 拦下**，处理后再启动）→ 记录执行情况（进展／问题／临时安排／实际差异／处理结果，只追加）。
2. 结束执行进入复盘；有资格的参与者提交反馈（1～5 分与文字），显示份数与平均分，无反馈时显示「暂无反馈」与「—」。
3. 说明要点：反馈资格在执行开始/结束时固定，归档后关闭；总结来源摘要固定当时的输入，来源变化后归档会被拦下要求重新核对。

### 第 7 幕 工作台与站内提示（1 分钟）

1. 组织概览页：卡片数值都有口径说明与「查看明细」，点进去能复算。
2. 待办清单点「处理」跳到对应活动；账号页站内提示可标记已读。
3. 说明要点：统计只来自真实业务记录，没有到场率、排行榜等无数据来源的指标。

### 第 8 幕 AI 文本辅助（3 分钟）

1. 组织设置 → AI 模型：填写协议、完整端点、模型 ID、密钥 → **保存**（保存不调用模型）→ **测试连接**（固定短文本）→ **启用**。密钥只提交不回显，改协议或地址必须重输密钥。
2. 活动草稿页：填写主题、目标、对象、人数、预算、时间地点、补充限制 → **生成草稿**（先「查看本次输入范围」确认会发送什么）→ 采用到编辑区 → 人工补充 → **保存方案**（生成不会自动建任务或改预算）。
3. 复盘页：生成总结草稿 → 采用 → 人工修改 → 保存 → **确认总结**；演示来源变化后的复核提示。
4. 异常演示：把模型配置停用或断开桩服务 → 生成返回明确错误码（超时 504 `AI_TIMEOUT`、上游认证 502 `AI_UPSTREAM_AUTH`），**页面原内容保留、可继续手工编写**，本站登录状态不受影响。
5. 说明要点：只发送本次生成必需信息（排除联系方式与凭据），资料放在定界块中且系统提示声明块内文字只是资料；生成记录与业务文稿分离，采用状态单独记录。

### 第 9 幕 归档、更正与只读（2 分钟）

1. 归档前条件不满足会被列出（待审报名、待确认费用、未结束任务、总结未确认或来源变化）；补齐后归档。
2. 归档后所有写入关闭（现场试一次任务变更 → 409）→ 组织负责人**重新打开**并填写理由 → 更正总结 → 重新确认 → 再次归档，历史留痕保留。
3. 取消活动：填写取消说明 → 报名与任务联动处理 → 归档（历史保留，不恢复报名与反馈）。

### 第 10 幕 一致性与安全（2 分钟，可用两个窗口同时操作）

1. 同一个活动在两个窗口同时编辑 → 后提交者收到 409 `EDIT_CONFLICT`（版本合同），不会静默覆盖。
2. 重复提交同一个创建请求（同一 `Idempotency-Key`）→ 返回同一资源，不产生重复草稿；同键不同内容 → 409 `IDEMPOTENCY_KEY_REUSED`。
3. 用外部账号访问组织内活动详情、名单、导出、附件 → 404（未发布活动对非负责人不可见）。
4. 退出登录后用旧页面写请求 → 401 `AUTH_REQUIRED`；缺少 CSRF 令牌 → 403 `CSRF_INVALID`。

## 三、收尾（1 分钟）

- 数据可复算：工作台数字、导出名单、经费统计三处口径一致（现场对照活动明细）。
- 交付物：源码、数据设计、接口说明、部署与恢复说明、验收复核记录、功能开发清单与开发日志。
- 明确未完成项：真实厂商模型调用未取证（需要密钥与额度）；性能结论限于单机开发环境的观测值。

## 四、常见提问与回答依据

| 提问 | 回答要点 | 依据位置 |
| --- | --- | --- |
| 为什么名额与金额不会并发出错？ | 锁协议：组织共享锁 → 活动锁 → 子记录；名额在活动行锁内判定，费用确认用活动行排他锁；事务隔离 READ COMMITTED | 后端架构与技术栈设计第五、六节；`RegistrationFlowTest`、`ExpenseFlowTest` 并发用例 |
| 版本号是做什么的？ | 编辑、方案、审批、状态动作都带期望版本，锁内比较后条件更新，过期返回 409 `EDIT_CONFLICT` | `EditConflictTest`、`ActivityChangeFreezeTest` |
| 为什么用防重键而不是查重？ | 未知结果的重试必须幂等：同键同内容返回同一资源，同键不同内容明确拒绝 | 开发规范第三节、`audit_f0507_flow.mjs` |
| AI 会不会自动改业务数据？ | 不会：生成记录与文稿分离，采用只写采用状态；保存与确认仍走原有业务端点并校验版本与来源 | 接口说明第七节、`AiGenerationFlowTest` |
| 密钥怎么保存？ | AES-GCM 加密，随机 nonce 与 keyId 一并保存，组织 ID 作为关联数据；查询只返回是否已配置；主密钥由部署环境保管 | 数据设计 V19、`AiConfigFlowTest` |
| 归档后为什么还要能改？ | 归档只读，但允许组织负责人**重新打开**并填写理由后更正，更正需重新确认总结，历史留痕不丢 | `ActivityLifecycleTest`、`audit_p9_flow.mjs` |
| 哪些功能明确没做？ | 签到／扫码／到场率、票据 OCR、自动审批与预测、在线支付与报销结算、外部渠道通知、多级组织树等 | 功能开发清单第六节 |
