**P0.2（token 与主题）：**

- `frontend/src/styles/tokens.css`：UI 规范 3.1 全量基线；为 Element Plus 语义组件新增 success／warning／danger／info 的 tint-3/5/7/8/9 与 dark 色阶 token（color-mix 派生，模式与 action 一致），UI 规范 3.1 已同步；UI 演示 tokens.css 与基线一致，以其为底复制。

- `npm run check:ui` 门禁（scripts/check-ui.mjs）：token 未定义引用、块内重复定义、自引用循环；业务文件颜色字面量、固定设计尺寸、font-family、动效时长字面量、`!important`、内联 style 绕过。tokens.css 作为值源排除，element-plus.css／base.css 纳入扫描。
- 联通检查页改造为 ElButton／ElTag／ElSkeleton／ElDialog，验证组件主题与传送弹层；页面样式全部消费 token。
- 验证：typecheck、lint、vitest（12 项）、check:ui、build 全部通过。

**P0.3（传输与错误合同）：**

- 前端 `shared/http/client.ts`：统一 Fetch 传输入口，支持 JSON／URLSearchParams／FormData／Blob／无响应体、超时与外部取消、CSRF 头 provider（会话层注册，仅非安全方法附加）、Content-Type 校验、X-Request-Id 透传；`error.ts` 定义 ProblemDetail 类型与 ApiError（server／transport 两类，不弹窗不跳转）。12 项单元测试覆盖 204、错误映射、字段错误、网络失败、取消、CSRF 注入与 blob。
- 后端：`RequestIdFilter`（X-Request-Id 生成/沿用 + MDC，先于 Security 过滤器链）；`GlobalExceptionHandler` 自管统一映射（ApiException、404、400 字段校验、405、415、500），输出 code／requestId／fieldErrors；SecurityConfig 过滤器层 401／403 写同一 ProblemDetail（AUTH_REQUIRED／CSRF_INVALID，no-store）；`GET /api/auth/csrf` 匿名返回原始 token 与 headerName（HttpSessionCsrfTokenRepository + 关闭掩码编码，不混用原始值与掩码值）。
- 验证：`mvnw test` 8 项全部通过（含合同探针端点的 CSRF／校验／404 检查）；真实联调复验健康检查、CSRF 端点、401 ProblemDetail 均正确。
- **重要经验：`spring.mvc.problemdetails.enabled=true` 会让框架在统一 advice 之前渲染 ErrorResponse 类异常（MethodArgumentNotValidException、NoResourceFoundException），导致 code/requestId 丢失；已移除该配置，由 GlobalExceptionHandler 独自负责全部 MVC 异常映射。**
- 运维注意：TaskStop 不会终止后端派生的 java 子进程，重启后端前需确认 8080 无残留监听（本次已发生并清理）。
