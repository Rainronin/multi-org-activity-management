# 接口说明

> 文档覆盖仍待补齐：P2 状态动作及 P3／P4 的字段、端点合同不完整。修改相关模块时对照现有迁移、Controller 与 DTO 补齐，不把缺失说明理解为尚无实现，也不得反向放宽计划书。当前审核结论见[开发进度审核报告](开发进度审核报告.md)。

用途：按开发规范第五节，在首个相关端点编码前记录方法、路径、字段、错误码、权限与恢复路径；按模块逐段增量维护，前后端共享同一份合同。路径、错误结构与传输约定以[开发规范](开发规范.md)第二节为唯一上位约定，本文不复制其规则，只登记模块字段与消费约定。

公共约定（全模块适用）：

- 路径或查询参数类型不匹配、数值溢出返回 400 `VALIDATION_FAILED`，`fieldErrors` 标明参数名，错误说明不回显原始值或转换异常；受保护端点仍先校验登录。
- 所有非安全方法必须携带 `X-CSRF-TOKEN`（匿名端点不豁免，开发规范 2.4）；CSRF 失败返回 403 `CSRF_INVALID`。
- 未登录访问受保护端点返回 401 `AUTH_REQUIRED`；登录失败与恢复失败统一返回 401 `AUTH_INVALID_CREDENTIALS`，不区分账号不存在与凭据错误。
- 会话绑定账号 `auth_version`：修改密码或恢复成功后版本 +1，旧会话请求一律 401 `AUTH_REQUIRED`；发起变更的当前会话由服务端更新绑定版本。
- 登录按账号+来源 IP 统计失败；恢复按连接来源 IP 统计全部尝试（每 5 分钟最多 10 次），不采信查询参数或客户端转发头。同一来源共享恢复额度，超限返回 429 `RATE_LIMITED` 并附 `Retry-After`（秒）。
- 响应 `Cache-Control: no-store` 适用于 CSRF、恢复及一切受保护 JSON。

## 账号模块（M01，P1.1）

| 端点 | 方法 | 请求 | 成功 | 主要错误 |
| --- | --- | --- | --- | --- |
| /api/auth/csrf | GET | - | 200 `{token, headerName}` | - |
| /api/auth/register | POST | JSON `{username, password}` | 201 `{id, username, recoveryCode}`；恢复码明文仅此一次返回 | 400 `VALIDATION_FAILED`（fieldErrors.username / fieldErrors.password）；409 `USERNAME_TAKEN`；429 `RATE_LIMITED` |
| /api/auth/login | POST | `application/x-www-form-urlencoded` `username`、`password` | 204（登录成功是 204 的明确例外） | 401 `AUTH_INVALID_CREDENTIALS`；403 `CSRF_INVALID`；429 `RATE_LIMITED` + `Retry-After` |
| /api/auth/me | GET | - | 200 `{id, username}`（id 为字符串） | 401 `AUTH_REQUIRED` |
| /api/auth/logout | POST | - | 204 | 403 `CSRF_INVALID` |
| /api/auth/recover | POST | JSON `{username, recoveryCode, newPassword}` | 200 `{recoveryCode}` 新恢复码明文仅此一次；同一事务：改密码、旧码 CONSUMED、发新码、auth_version+1 | 401 `AUTH_INVALID_CREDENTIALS`（不泄露账号或码状态）；429 `RATE_LIMITED` |
| /api/auth/recovery/reissue | POST | JSON `{currentPassword}`，需登录 | 200 `{recoveryCode}`；旧码 REVOKED、发新码 | 401 `AUTH_INVALID_CREDENTIALS`；401 `AUTH_REQUIRED` |
| /api/auth/password | POST | JSON `{currentPassword, newPassword}`，需登录 | 204；auth_version+1，旧会话失效 | 401 `AUTH_INVALID_CREDENTIALS`；400 `VALIDATION_FAILED` |

字段校验：`username` 3～32 位 `^[a-zA-Z0-9_]{3,32}$`；`password` 与 `newPassword` 8～72 位且同时包含字母与数字；恢复码格式为服务端发放的分段十六进制串，比较前忽略大小写与连字符、空格。

防重与结果恢复路径：注册重复提交以账号唯一约束兜底返回 409 `USERNAME_TAKEN`，不产生第二个账号；恢复码已消费后重放统一 401，结果丢失时用户以新密码登录后可重新签发，不引入额外防重表（开发规范 2.5 的幂等键要求自首个可能重复计费／建单的动作起适用）。

前端消费约定：

- 注册、恢复、重签响应中的 `recoveryCode` 仅展示一次，界面要求用户明确确认已保存后才能离开；不写入 localStorage、日志或 URL。
- 登录页 401 就地显示，不触发全局登录跳转；受保护请求的 401 `AUTH_REQUIRED` 由会话层单飞处理，只引导一次登录且核对会话代次，旧响应不清除新登录。
- `CSRF_INVALID` 时前端刷新 CSRF 凭据并提示重试，不自动重放写请求。
- 登录回跳参数仅允许站内相对路由。

## 组织模块（M01，P1.2）

权限：全部要求登录；组织详情仅有效成员可见，非成员一律 404 `RESOURCE_NOT_FOUND`（不泄露组织存在性）。角色只有 `OWNER`（组织负责人）与 `MEMBER`；负责人授予／撤销属 P1.3。

| 端点 | 方法 | 请求 | 成功 | 主要错误 |
| --- | --- | --- | --- | --- |
| /api/organizations | POST | JSON `{name, description?}` | 201 `{id, name, description, role: "OWNER", joinedAt}`；创建者自动成为首位组织负责人（同事务） | 400 `VALIDATION_FAILED` |
| /api/me/organizations | GET | - | 200 `{items: [{id, name, role, joinedAt}]}`（本人有效成员关系，按加入时间升序） | 401 `AUTH_REQUIRED` |
| /api/organizations/{orgId} | GET | - | 200 `{id, name, description, role, memberCount, createdAt}`（role 为本人角色） | 404 `RESOURCE_NOT_FOUND`（非成员或不存在的组织同一响应） |

字段校验：`name` 1～64 字符（服务端 trim）；`description` ≤512 字符可空。

防重与结果恢复路径：组织创建重复提交会产生多个组织（无唯一键），首期不为建组引入幂等键——前端按钮提交期间禁用即可；此豁免记录在案，首个涉及金额或名额的动作起启用 `Idempotency-Key`。

前端消费约定：

- 当前组织由 URL（`/org/:orgId/...`）决定，不写入服务端会话、不作为授权依据；store 中组织目录按 orgId 索引，不保存可写的 currentOrgId。
- 组织切换：切换路由即切换数据作用域；页面请求全部携带 orgId 并在响应返回时核对归属，迟到响应不渲染；切换前如出现未保存内容按统一未保存提示处理（首次出现真实编辑场景时引入 useUnsavedChanges）。
- 非成员访问组织详情返回 404 时展示"组织不存在或无权访问"，不区分两种原因。

## 组织成员与邀请（M01，P1.3）

成员变更须遵守下方权限、职责与幂等合同。

权限：全部要求登录且为该组织有效成员；成员管理动作（邀请、授予／撤销负责人、移交、移除）仅组织负责人（OWNER）。成员标识 `memberId` 为成员关系行 id。所有变更在组织行排他锁内校验并提交；关键动作写审计。

| 端点 | 方法 | 请求 | 成功 | 主要错误 |
| --- | --- | --- | --- | --- |
| /api/organizations/{orgId}/invitations | POST | JSON `{expiresInDays?, maxUses?}`（默认 7 天／10 次，范围 1-30／1-100） | 201 `{invitationId, code, expiresAt, maxUses}`；邀请码明文仅此一次返回（存哈希，之后不可查看） | 403 `FORBIDDEN`；404 `RESOURCE_NOT_FOUND` |
| /api/organizations/{orgId}/invitations | GET | - | 200 `{items: [{invitationId, createdBy, createdAt, expiresAt, maxUses, usedCount, status}]}`（不含明文） | 403；404 |
| /api/organizations/{orgId}/invitations/{invitationId}/revoke | POST | - | 204 | 403；404（含非本组织的邀请 id） |
| /api/invitations/accept | POST | JSON `{code}` | 200 `{orgId, name, role: "MEMBER"}`；已是有效成员时幂等返回现有关系，不重复计数。被移除（REMOVED）成员仅可凭**移除之后创建**的邀请重新加入（复用主关系行，memberId 不变），旧邀请返回 400；自行退出（LEFT）成员可凭任何有效邀请重新加入 | 400 `INVITATION_INVALID`（无效／过期／撤销／已满／被移除者用旧码统一此码）；401 `AUTH_REQUIRED` |
| /api/organizations/{orgId}/members | GET | `?page=1&pageSize=20&query=`（page 从 1 起，pageSize 默认 20 上限 100，query 按用户名模糊过滤） | 200 `{items, page, pageSize, total}`（仅有效成员，固定按加入时间排序） | 400 `VALIDATION_FAILED`；404 |
| /api/organizations/{orgId}/members/me | DELETE | - | 204 退出组织；关系置 LEFT，历史保留，可凭有效邀请再加入（重复退出幂等 204）。**S07-B：退出前先检查职责，再取消该账号在“尚未进入执行的内部活动”中的待审／有效报名**（改写为 `CANCELLED_ORG`、保留原因、释放名额、写审计 `REGISTRATION_CANCELLED_ON_LEAVE` 与 `REGISTRATION_CANCELLED` 提示意图）；已开始活动与公开活动报名保留为历史 | 409 `LAST_OWNER_PROTECTED`（最后一名负责人须先移交）；409 `MEMBER_HAS_ACTIVITY_DUTIES`（仍负责未归档活动，须先变更活动负责人）；409 `MEMBER_HAS_OPEN_DUTIES`（有未完成任务或未就绪物资） |
| /api/organizations/{orgId}/members/{memberId} | DELETE | - | 204 移除成员（OWNER）；关系置 REMOVED，历史保留。**已授权操作者的重复移除幂等返回 204**；对无权用户保持资源隐藏。职责检查与报名联动同退出，操作者记为该次操作的执行者 | 409 `LAST_OWNER_PROTECTED`；409 `MEMBER_HAS_ACTIVITY_DUTIES`／`MEMBER_HAS_OPEN_DUTIES`；400 `MEMBER_SELF_REMOVAL`（移除自己请用退出）；403；404（成员不属于该组织） |
| /api/organizations/{orgId}/members/{memberId}/promote-owner | POST | - | 200 `{memberId, role: "OWNER"}`；目标须为有效普通成员 | 409（已是负责人→`MEMBER_ALREADY_OWNER`）；403；404 |
| /api/organizations/{orgId}/members/{memberId}/revoke-owner | POST | - | 200 `{memberId, role: "MEMBER"}`；可撤销包括自己在内的 OWNER，但剩余 OWNER ≥2 | 409 `LAST_OWNER_PROTECTED`；403；404 |
| /api/organizations/{orgId}/ownership/transfer | POST | JSON `{toMemberId}` | 200 `{role: "MEMBER"}`（调用者降为成员）；同事务完成授予与自降，组织始终至少一名 OWNER | 400（移交给自己）；409；403；404 |

字段校验：邀请码比较前忽略大小写、连字符与空格；`expiresInDays` 1～30、`maxUses` 1～100。

防重与结果恢复路径：邀请接受以"组织排他锁 + 成员唯一约束 + used_count 条件更新"三重保护，重复接受幂等返回；退出/移除重复提交幂等（关系已非 ACTIVE 时返回 204，不重复变更）；授予／撤销以当前角色状态校验，冲突返回 409。

前端消费约定：

- 邀请码创建后仅展示一次，提供复制入口并提示"关闭后不可再次查看"；邀请列表只显示次数与状态。
- 最后负责人相关操作（退出、移除、撤销、移交目标校验）失败时提示"组织至少保留一名负责人，请先移交"。
- 成员退出后立即可感知失权：后续请求按 401／404 处理并清空该组织已加载数据。
- 成员管理动作全部要求二次确认（移除、移交为不可逆业务动作）。

## 活动模块（M02，P2.1 起：草稿创建、列表与编辑）

权限：创建仅组织负责人（OWNER），创建时须指定本组织有效成员为活动负责人；未发布（草稿／待确认）活动仅组织负责人与被指定的活动负责人可见可编辑，普通成员只能看到已确认活动、以及本人负责的未发布活动。列表、详情与任务／物资／附件等子资源使用同一可见性（S06，第二轮修复）。所有请求带组织范围，非本组织资源一律 404。写操作取组织行共享锁校验成员资格。

| 端点 | 方法 | 请求 | 成功 | 主要错误 |
| --- | --- | --- | --- | --- |
| /api/organizations/{orgId}/activities | POST | **请求头必带 `Idempotency-Key`（1～64 字符）**；JSON `{name, ownerMemberId, description?, startTime?, endTime?, location?, budget?, registrationScope?, capacity?, registrationStart?, registrationEnd?}`（时间 ISO-8601 带偏移；budget 两位小数字符串，默认 "0.00"） | 201 活动资源（含 id、全部字段与 `version`；`registrationOpen` 默认 false）。同键同内容重放同样返回 201 与原资源 id，不重复建草稿 | 400 `IDEMPOTENCY_KEY_REQUIRED`（缺键或超长）；400 `VALIDATION_FAILED`（字段/时间顺序）；400 `ACTIVITY_OWNER_INVALID`（负责人非本组织有效成员）；403（先于防重键校验，非组织负责人）；409 `IDEMPOTENCY_KEY_REUSED`（同键内容不同）；404 |
| /api/organizations/{orgId}/activities | GET | `?page&pageSize&query&status`（分页合同；status 白名单 DRAFT｜PENDING_APPROVAL｜APPROVED） | 200 `{items, page, pageSize, total}`；OWNER 见全部状态，其他成员见已确认活动及本人负责的未发布活动，`total` 与 `items` 同条件 | 400；404 |
| /api/organizations/{orgId}/activities/{activityId} | GET | - | 200 活动资源（未发布仅 OWNER 与活动负责人；含 `confirmedAt`） | 404（非可见者与不存在同响应） |
| /api/organizations/{orgId}/activities/{activityId} | PATCH | JSON 任意字段子集（同创建字段；`ownerMemberId` 仅 OWNER 可改且目标须有效成员）；**必带 `version`** | 200 更新后活动资源 | 400 `VALIDATION_FAILED`（缺 `version`）；400（字段／时间顺序）；403；404；409 `EDIT_CONFLICT`（版本过期）／`ACTIVITY_SCOPE_LOCKED`／`ACTIVITY_CAPACITY_BELOW_APPROVED`／`ACTIVITY_STATE_CONFLICT` |
| /api/organizations/{orgId}/activities/{activityId} | DELETE | - | 204 无响应体（仅 `confirmed_at` 为空且无任务／物资／附件／有效报名的草稿） | 403；404；409 `ACTIVITY_DELETE_CONFLICT`／`ACTIVITY_HAS_DEPENDENCIES` |
| /api/organizations/{orgId}/activities/{activityId}/registration-open | POST | JSON `{open: boolean}` | 200 更新后活动资源（`registrationOpen` 生效） | 403（既非 OWNER 也非活动负责人）；409 `ACTIVITY_STATE_CONFLICT`（非已确认状态或活动已开始）；404 |

报名开关（S02，第二轮新增）：独立于报名时间窗，仅组织负责人或活动负责人可变；仅已确认且未到开始时间允许变更；撤回已确认活动会把开关复位为关闭。开关只阻止新申请，不阻止审核既有申请、驳回待审与合法取消（后端架构 5.2）。

关键变更冻结（S07-A，第三轮新增）：`activity.confirmed_at` 记录最近一次立项确认时间；`DRAFT` 且该值非空表示调整期待确认，此时任务与物资写操作返回 409 `ACTIVITY_STATE_CONFLICT`（“活动安排调整中”），活动也不得按初始草稿删除。PATCH 与删除的附加约束：

| 场景 | 结果 |
| --- | --- |
| 活动已有任意报名主记录（含已取消／已驳回）时提交不同的 `registrationScope` | 409 `ACTIVITY_SCOPE_LOCKED`，附现有报名条数 |
| 提交的 `capacity` 小于当前已通过报名数 | 409 `ACTIVITY_CAPACITY_BELOW_APPROVED`，附已通过人数 |
| 提交的 `budget` 小于当前已确认支出合计 | 409 `ACTIVITY_BUDGET_BELOW_APPROVED`，附已确认支出金额（P5.3 起，与容量下限同一处理方式） |
| 删除 `DRAFT` 活动，但 `confirmed_at` 非空 | 409 `ACTIVITY_DELETE_CONFLICT`（曾通过立项确认，不得按初始草稿删除） |
| 删除 `DRAFT` 活动，但已有任务／物资／附件／有效报名 | 409 `ACTIVITY_HAS_DEPENDENCIES`，`detail` 列出依赖类型 |

字段校验：`name` 1～128；`description` ≤2000；`budget` ≥0 两位小数（超精度拒绝）；`capacity` 正整数或空；时间齐备时 `startTime < endTime`、`registrationStart < registrationEnd ≤ startTime`、`capacity` 与报名窗口在启用公开报名时必填（P4 收紧，当前草稿宽松记录）。

创建防重与结果恢复沿用本节 Idempotency-Key 合同，不另设豁免。

前端消费约定：活动列表按当前成员与活动可见性开放，创建对话框仅对组织详情接口确认为 OWNER 的用户展示，不能根据活动列表是否有数据推断角色；负责人候选列表明确区分加载、失败重试与空结果，加载或失败时禁止保存，关闭弹窗后丢弃迟到响应；列表页随路由 orgId 重建（沿用成员页的序号与代次守卫模式）；金额输入用字符串保存不经浮点；时间展示 `Asia/Shanghai`。

创建表单消费：仅主题与负责人必填，选填项按基本信息、时间地点、预算报名分组；前端校验长度、非负两位小数金额、结束晚于开始及正整数名额，服务端仍逐请求校验。时间输入明确标注北京时间并提交 `+08:00`；成功后提供进入草稿详情的入口，保存草稿不自动开放报名。明确 400／403／404／422／429 拒绝可重新编辑并使用新防重键；网络异常、409 或 5xx 保留原键及原内容核对，不自动重发、不允许改内容重试。暂存只在当前页面内存中；离开或刷新前提醒核对结果。

任务页面消费：活动任务及本人任务显示已有 `description`，活动任务显示 `dueAt`；本人任务的活动入口定位 `?tab=tasks`。任务创建／编辑使用现有接口，标题与负责人必填，说明最多 2000 字符；保存错误显示在弹窗内，取消有未保存提醒，不改变分派权限或状态规则。


编辑冲突与防重（S08，第五轮新增；F05 收紧）：活动、任务、物资的响应都带整数 `version`，每次成功写入 +1。

- **必带版本**（缺失即 400 `VALIDATION_FAILED`，`fieldErrors[0].field = version`）：活动 PATCH、方案保存 `PUT /proposal`、审批 `POST /approve`、`POST /reject`、`POST /withdraw-approval`、任务改派 `POST /tasks/{taskId}/update`、物资更新 `POST /materials/{materialId}/update`。
- **版本不符**：409 `EDIT_CONFLICT`，不写入任何字段；前端刷新详情后由用户重新决定。方案保存与审批都按“读到哪一版就审哪一版”校验，因此撤回重提后基于旧版本的审批不会确认新内容。
- **不需要版本**：`POST /submit`、`POST /withdraw`、`POST /registration-open` 以源状态作为等价前置条件（单源状态 CAS，影响行数为 0 即 409 `ACTIVITY_STATE_CONFLICT`）。
- 创建活动必须带 `Idempotency-Key`；服务端以 `uk_activity_org_request_key (org_id, request_key)` 唯一约束兜底并发重放。
- 锁协议（F04 补齐）：写入口一律先按「组织行锁 → 活动行锁 → 子记录」取锁，再在锁内重新读取身份、活动与目标记录后才判断权限与状态；子记录写入用 `FOR SHARE`，活动自身与跨子记录写路径用 `FOR UPDATE`。报名审核在锁内重读活动状态与报名记录后再校验名额。

附件校验与时序（S09，第六轮新增）：上传先做粗粒度权限检查，再在受控暂存目录完成大小、扩展名、Content-Type 与内容嗅探（PNG／JPEG／GIF／WEBP／PDF／ZIP 按魔数，文本类型判 NUL 与控制字符；扩展名与 Content-Type 必须自洽），通过后以随机不可变存储名移入持久目录，最后在短事务内按锁协议复检权限并登记；登记失败只在确认无数据库引用时清理本次文件，结果未知不删除。删除先在事务中标记失效，提交后再清理磁盘，失败保留重试依据。响应含 `purpose`（`ACTIVITY_DOC` 或 `TASK_ATTACHMENT`）与 `taskId`。调整期待确认期间资料只读（上传 409），下载仍可用。

任务附件（S10，第八轮新增）：附件二选一关联活动或任务，任务资料额外提供 `POST`／`GET /api/organizations/{orgId}/activities/{activityId}/tasks/{taskId}/attachments`，权限为组织负责人、活动负责人或该任务承担者（上传与删除都按此规则，下载与列表沿用活动可见性）；活动级资料列表不含任务资料，不同任务的资料互不可见；任务不属于该活动时统一 404。

公开浏览（S11，第九轮新增）：`GET /api/public/activities`、`GET /api/public/activities/{activityId}` **允许匿名访问**。只返回「已确认且报名范围 PUBLIC」的活动（内部活动面向本组织成员，走组织内端点），字段仅含 `id、organizationName、name、description、location、startTime、endTime、registrationScope、capacity、registrationStart、registrationEnd、registrationOpen、updatedAt`；预算、方案、审批信息、负责人、任务与附件一律不下发，草稿与撤回待确认的活动返回 404（与不存在同响应）。

名单导出（S11，第九轮新增）：`GET /api/organizations/{orgId}/activities/{activityId}/registrations/export?status=`，权限与筛选同管理名单（组织负责人或本活动负责人），单次上限 5000 行，写审计 `REGISTRATION_EXPORTED`。响应为 `text/csv;charset=UTF-8`（带 BOM），单元格统一加引号并把 `=`、`+`、`-`、`@`、制表、回车开头的文本前置单引号，防止表格软件把用户填入的姓名／备注当公式执行；字段固定为报名主记录，不含联系方式等额外信息。F09 起超过上限返回 409 `EXPORT_TOO_LARGE`（附总数与上限），不再静默截断；上限可由 `app.registration.export-max-rows` 配置。

**普通活动编辑边界：** `PATCH /api/organizations/{orgId}/activities/{activityId}` 仅允许草稿按既有字段规则修改，筹备中仍仅允许组织负责人修改简介；待确认、执行、复盘、取消及归档状态返回 409 `ACTIVITY_STATE_CONFLICT`。执行后的实际更正走执行记录，重新打开后仍遵循所处状态规则。

**物资写入边界：** 新增、编辑和状态流转统一在组织及活动锁内检查 `isPreparationWritable()`；筹备、执行与复盘可维护，初始草稿、待确认、调整期待确认、取消和归档只读，拒绝返回 409 `ACTIVITY_STATE_CONFLICT`。

**票据下载边界：** 通用附件下载端点遇到 `EXPENSE_VOUCHER` 时，与费用凭证列表一样要求组织负责人或该活动负责人；其他成员返回 404，不泄露票据是否存在。普通活动及任务资料仍按原活动可见性读取。

**只读边界（P6.5）：** 归档后任务、物资、附件、费用与执行记录全部拒绝写入；已确认或已作废费用的凭证不可删除；归档资料删除需先由组织负责人重新打开活动。

**总结来源摘要（P6.4）：** 确认总结时保存来源摘要（活动事实、任务、报名、费用合计、执行记录数、反馈份数与均分，固定字段与稳定排序）；归档时在同一事务内重算比较，任何来源变化都会以 `ARCHIVE_BLOCKED`（detail 含「来源已变化」）要求重新核对并确认。

| …/ai/generations | GET | `?type` | 200 最近 5 条生成记录（含 `sourceChanged` 来源变化标记、`missing` 缺失项） | 400；403；404 |
| …/ai/generations/{generationId} | GET | - | 200 记录详情；撤权或状态不再允许时按不可见处理 | 403；404 |
| …/ai/generations/{generationId}/adopt | POST | - | 200 记录人工采用时间与账号 | 409 `AI_GENERATION_NOT_READY`；403；404 |

方案生成条件（`conditions`）：`topic`≤200、`goal`≤500、`audience`≤200、`expectedParticipants` 1～100000、`budget`≤200、`timePlace`≤200、`constraints`≤500；至少填写主题或目标，未填写项由模型标注“假设”或“待补充”。

生成编排（后端架构 6.3）：短事务取授权输入与来源版本并写请求记录 → **事务外**调用模型 → 短事务复核权限、活动状态与配置修订后保存结果。

- 权限：方案生成与手工保存方案一致（仅活动草稿期、组织负责人或活动负责人，未发布活动对他人 404）；总结生成与手工总结一致（复盘期或取消后的遗留处理期且未归档）。非成员 404，其他成员 403。
- 防重：同组织、同操作者、同 `Idempotency-Key` 且内容相同只调用一次模型并返回既有记录；内容不同返回 409 `IDEMPOTENCY_KEY_REUSED`；并发首次提交撞唯一键返回 409 `REQUEST_IN_PROGRESS`，使用原键重试取得已有记录，不发起第二次模型调用；重放同样重新鉴权，不返回撤权前的草稿（F01 口径）。
- 输入：只发送本次生成必需的信息（活动事实、已确认方案、任务、报名汇总、执行记录、已确认费用与反馈要点），排除联系方式、账号凭据、通知与访问日志；人数、金额与比例由程序先算好再交给模型；资料统一放在定界块（`【资料开始】…【资料结束】`／`【条件开始】…【条件结束】`）中，系统提示声明块内文字只是资料，诱导指令不改变任务、权限或触发操作。
- 输出：只取最终正文（忽略推理块与工具块）；空正文、拒绝、非法结构、截断与超长都返回明确错误，不当作成功草稿；输出按纯文本入库，前端只按文本显示，不执行其中的 HTML 或脚本。
- 结果：调用期间配置被修改或停用返回 409 `AI_CONFIG_CHANGED`（不自动采用、不换用新配置补发，已产生的文本只保留在受限生成记录中作为核对依据）；调用期间撤权或活动状态变化返回原鉴权错误并把记录标为 `AI_PERMISSION_REVOKED`；遗留 `RUNNING` 记录在超过时限后的查询／生成时转为 `FAILED`（`AI_CALL_ABORTED`），不无限挂起。
- 采用：`adopt` 只写采用状态；方案保存仍走 `PUT …/proposal`，总结保存与确认仍走 `PUT …/summary` 与 `…/summary/confirm`，版本与来源校验不变；归档后不再生成总结。

### 7.3 调用限额、地址边界与错误映射

- 限额（`app.ai.*`，均有代码默认值）：单实例并发 `max-concurrent-calls`＝2；组织频率 `max-calls-per-five-minutes-per-org`＝10；组织当日额度 `max-calls-per-day-per-org`＝50（按持久生成记录统计，含连接测试）；输入字符上限 `max-input-chars`＝8000；响应体字节上限 `max-response-bytes`＝262144；草稿字符上限 `max-draft-chars`＝20000；连接超时 `connect-timeout-seconds`＝5。部署级总开关 `app.ai.enabled=false` 时全部 AI 入口返回 503 `AI_DISABLED`。
- 地址边界：只允许 HTTPS、部署允许的域名清单（`app.ai.allowed-hosts`，支持 `*.example.com` 通配）与 443 端口；禁止 userinfo、片段与携带凭据的 query；保存与调用共用同一校验，每次调用前重新解析域名并拒绝回环、私网、链路本地与云元数据地址；关闭重定向（不把密钥转发到另一主机）。本机验证开关 `app.ai.allow-private-hosts=true` 仅供测试环境，默认关闭，生产不以它代替受限出口（部署说明记录域名清单与出口要求）。
- 上游错误映射（响应回传本次服务端请求标识 `requestId`，不回传密钥；错误文本先脱敏）：

| 上游情况 | 本站响应 |
| --- | --- |
| 401／403 | 502 `AI_UPSTREAM_AUTH`（**不**映射为本站登录失效） |
| 404 | 502 `AI_UNSUPPORTED_MODEL` |
| 429 | 429 `AI_UPSTREAM_RATE_LIMITED` |
| 其它 4xx | 502 `AI_UPSTREAM_REJECTED` |
| 5xx／连接失败 | 502 `AI_UPSTREAM_ERROR`／`AI_CONNECT_FAILED` |
| 超时 | 504 `AI_TIMEOUT` |
| 响应过大 | 502 `AI_RESPONSE_TOO_LARGE` |
| 空正文／拒绝／结构异常 | 502 `AI_INVALID_OUTPUT` |
| 截断（`finish_reason=length`／`stop_reason=max_tokens`） | 502 `AI_OUTPUT_TRUNCATED` |
| 输出超过草稿上限 | 502 `AI_OUTPUT_TOO_LONG` |

协议适配实际发送的字段（不开放任意请求头或任意 JSON 模板）：

| 协议 | 认证 | 请求体 |
| --- | --- | --- |
| OpenAI Chat Completions | `Authorization: Bearer` | `model`、`messages`（system＋user）、`stream=false`、`max_tokens` 或 `max_completion_tokens`；取 `choices[0].message.content`（兼容分段数组） |
| Anthropic Messages | 默认 `x-api-key`（兼容网关可选 Bearer）＋ `anthropic-version: 2023-06-01` | `model`、`max_tokens` 必填、`system` 与 `messages` 分离、`stream=false`；按顺序合并 `content` 中的 `text` 块 |
