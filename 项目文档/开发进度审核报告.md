### 必须修正的问题

1. **R01 · 中：静态门禁本身使 lint 失败。** `frontend/scripts/check-ui.mjs:166、168、172` 的 `for (const match …)` 未使用 match，触发三处 `@typescript-eslint/no-unused-vars`。修掉无用绑定并重新执行 lint；“所有检查通过”与当前提交不符。
2. **R02 · 中：AI 卡按钮未定位到承诺的编辑区。** `WorkbenchSection.vue:380` 的“打开复盘／方案编辑”调用通用 `openActivity`，只跳活动详情；`ActivityDetailPage.vue:57` 默认 `overview`，不读取目标页签。独立点击总结入口实际到 `/org/4922/activities/4015`，选中仍为“概览”。应通过已有路由传递目标，详情校验当前状态／权限后选中方案或复盘页签；补两种入口的最小浏览器检查。
3. **R03 · 中：登录对照证据无效。** `生成脚本/audit_ui_workbench.mjs` 在已登录 ctx 中访问 `/login`，被守卫跳到账号页；`UI核对-登录-1440.png` 实际是账号页。用独立匿名 context，断言最终路径与登录表单，再截图并更新对照页。独立复核的正确截图见[真实登录页](../验证截图/UI独立审核/独立复核-登录.png)；登录实际外观本轮局部通过，失败的是原证据链。
4. **R04 · 中：390px 导航不够紧凑。** 实拍中深色导航占据很大的首屏高度，菜单图标与文字纵向排列，分组标题窄列折行，主体在导航下方很晚才出现。规范要求紧凑文档流导航；应修正手机分组／菜单排列，复用现有导航，避免再增加一套导航。验收看首屏可用性，不能只看 overflow=0；补 320／768／1024 及短屏检查。
5. **R05 · 中：U02 仍有可见的密度失衡。** `WorkbenchSection.vue` 的 `.content-grid` 将较短经费图与长明细放同一行；待办位于后续，左下形成大块空白。明细仍将多条统计口径／开发限制完整常驻。收起非必要口径，压缩明细并合理安排待办；经费环目前没有可见百分比，可加真实占比标签（不要只放 aria-label）。不要求新增趋势接口或伪造曲线。

## 二、证据与具体偏差

[本机同视口对照页](../验证截图/UI独立审核/对照.html)包含参考／正式工作台、参考／正式登录以及正式活动列表和详情。截图为本轮实拍；参考数据与真实业务数据不同，判断比较布局而不是姓名和数值。

### U01 · 高：工作台信息架构没有还原

规范要求“深色重点活动卡＋暖橙 AI 卡 → 精简 KPI → 图表 → 明细”。[WorkbenchSection.vue](../基于Vue3的多组织活动管理系统_zcode/frontend/src/features/workbench/WorkbenchSection.vue) 实际将 cards 与 myCards 合并，放在单个白色 section 中，以 dl 网格平铺，再列待办；没有重点活动卡、AI 卡或图表构图。

[OrgOverviewPage.vue](../基于Vue3的多组织活动管理系统_zcode/frontend/src/features/organization/OrgOverviewPage.vue) 又把组织简介／成员数／角色／创建时间放在工作台前，占用首屏主位置。本轮测试组织已有已确认活动与任务，仍显示这种结构，不能归因为空数据或功能未开发。

**还原要求：**将工作台作为行动入口，组织资料缩到适当位置；按 FocusBoard.vue 恢复主活动与 AI 双卡、按 Overview.vue 恢复少量 KPI 和后续数据层级。真实数据按权限接入；无候选活动／未配置 AI 使用同构空态，不取消整个设计区域。图表仅使用现有真实统计；没有趋势接口时先明确缺口，不伪造曲线或擅自扩业务。

### U02 · 高：卡片、排版与阅读层级退化为字段平铺

正式工作台约 15 个指标放进一个大框，单项没有独立卡片边界、图标与重点取舍；大量口径说明与数字一起展示，抢占主内容。[WorkbenchSection.vue](../基于Vue3的多组织活动管理系统_zcode/frontend/src/features/workbench/WorkbenchSection.vue) 的 dd 未重置默认左边距，也没有使用数据字体，数值与标签错位。

本轮 body 计算样式确为既定字体栈、14px，所有 CSS 引用的 --ui-* 均有定义。**不是字体文件未加载或 token 全丢失，主要是消费方式、HTML 默认样式和组件组合未做到位。** 统一 token 是必要条件，不会自动产生 Demo 的布局。

还原：数据单项卡片、等宽数字、标题／辅助文案层级、卡片间距与白空间；将详细口径移至适当说明入口，保留必要的业务提示。

### U03 · 高：活动详情成为纵向功能堆叠

[ActivityDetailPage.vue](../基于Vue3的多组织活动管理系统_zcode/frontend/src/features/activity/ActivityDetailPage.vue) 及其子区块按开发阶段陆续插入任务、物资、资料、报名、经费、执行／总结／AI，缺少统一详情布局。本轮仅一个活动和一条任务，详情全页已约 2708px。重要安排和行动位置被多个功能区挤散。

还原：顶部活动概览与当前状态／主操作，后续按既有详情与业务页签要求组织内容，不在每次新增功能时继续往下堆块。以 App.vue 的详情表达为参考；正式业务可以有完整详情路由，不机械把所有功能塞回 Demo 抽屉。复用区块标题、工具条、空态、表格与编辑弹层。

### U04 · 中：侧栏外形与分屏登录保留，但细节仍偏离

不能说“毫无相似”：近黑悬浮侧栏、黑白橙、浅底以及登录左右分屏确实存在，应保留。正式导航当前为平铺菜单，选中项变成较高矩形并贴到右侧边缘，缺少 Demo 的分组／子级和紧凑圆角项；多模块入口增加时未遵循原导航层级。

正式登录保留品牌文案与分屏方向，但顶部品牌图形成了三个圆点，与原倾斜线条标识不同。应对照 sidebar.css、App.vue、LoginPreview.vue 恢复控件比例、品牌标识、选中状态和留边；不要再换另一套后台模板。

### U05 · 中：玻璃质感、微交互及加载节奏基本没有迁移

正式 src 中未发现 GSAP 使用或对关键卡片的 motion-lift／surface-glass 消费；工作台加载仅为文本提示。规范中的主卡质感、卡片悬停、错峰进入、对应骨架层级没有因统一 token 自动落地。

不要求为了动效安装新库：简单悬停／状态先用 CSS，已有 GSAP 适用时用于必要入场与数值变化，统一消费 token，保留 reduced-motion、卸载清理。不要增加假延时或装饰性复杂动画。

### U06 · 高：UI 检查验错了目标，完成声明超出证据

check:ui 主要检查 token 定义、样式字面量等静态约束；手机检查主要验证页面宽度、错误及部分操作。它们均不判断主活动卡、AI 卡、KPI 层级、图表和导航是否与 Demo 相似。

本轮确认没有未定义 token，但这不能证明视觉合格。静态检查还存在规则脆弱点，例如组件数值 props 正则的边界字符异常，应修规则并留能命中反例的小检查；无需建设庞大的视觉测试平台。

**验收必须补：**同视口、同角色、可比数据状态的 Demo／正式截图并排审查；桌面展开／折叠、手机、加载／空态／失败、失焦校验／弹层、减少动效均有明确结果。不能再写“0 页面错误、0 溢出，因此 UI 完成”。
