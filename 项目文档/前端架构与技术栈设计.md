# 前端架构与技术栈设计

本文维护当前正式工程的实现职责与技术边界。业务权限以[项目计划书](项目计划书.md)为准，共同合同遵守[开发规范](开发规范.md)；完成状态与测试结果见[审核报告](开发进度审核报告.md)，单次修复过程见开发日志。初版功能清单已关闭，尚未部署生产。

## 一、技术边界

| 用途 | 当前选型 | 使用方式 |
| --- | --- | --- |
| 应用 | Vue 3、TypeScript、Vite | 单页应用，Composition API，统一 `<script setup lang="ts">`，strict 检查 |
| 路由 | Vue Router | 单一静态路由注册，业务页面懒加载 |
| 跨页面状态 | Pinia | 只存会话身份及组织目录等实际共享状态，不把所有接口响应存进全局 |
| 业务组件 | Element Plus 及配套图标 | 首期显式导入；表格、表单、上传、弹窗等直接使用，不重新实现 |
| 样式 | CSS、scoped、CSS 自定义属性 | 设计数值统一来自 tokens.css，主题映射遵循 UI 规范；不安装 Tailwind 或建立主题平台 |
| 请求 | 原生 Fetch | 一个传输入口，业务模块提供具名接口函数 |
| 检查 | TypeScript、ESLint、Vitest（有组件测试需求时再引入 Vue Test Utils） | 类型、规范及有业务风险的组件／状态检查 |
| 包管理 | npm | 锁定依赖，支持干净安装与构建 |

GSAP 已用于获认可的 UI 演示；正式工程当前未安装GSAP，以现有CSS／Vue过渡为准，只有实际动效需求无法满足时再评估。Vue Bits 当前未使用；两者不能替代业务组件库。也不预装图表、富文本、通用工具合集、请求缓存或全套后台模板。

标准能力优先：表单交互用 Element Plus，日期展示用 Intl，查询参数用 URLSearchParams，读取取消用 AbortController，简单动画用 CSS／Vue Transition。依赖事实参考 [Vue 官方工程入口](https://vuejs.org/guide/quick-start.html)及 [Element Plus 组件目录](https://element-plus.org/en-US/component/overview.html)。确切版本在工程初始化时记录并实际验证。

## 二、目录的唯一划分

采用按功能聚合的目录，不同时维护全局 `views/`、全局业务 `api/` 与另一套 `features/`。下面是当前正式源码目录；只随实际文件创建目录。

```text
frontend/
  src/
    main.ts
    App.vue
    router/                  路由、路由元信息与登录引导
    layouts/                 AuthLayout、OrganizationLayout、PublicLayout
    stores/                  session.ts、organizations.ts
    shared/
      http/                  client.ts、error.ts、idempotency.ts、协议层类型
      components/            ListPage.vue（列表页页头／筛选／面板／四态）
      utils/                 readUiToken.ts（readUiLength／readUiDuration）、useLoadingSkeleton.ts
    features/                按业务模块建立，与后端 modules 大致对应
      account/               登录、注册、恢复、账号页与恢复码弹窗
      organization/          目录切换、创建／加入组织、成员、组织概览与设置
      activity/              活动列表与详情、任务物资资料（P3）、报名、公开活动
      expense/               经费明细与统计
      feedback/              反馈数据访问
      notification/          站内提示
      workbench/             分身份工作台
      ai/                    模型配置与文稿面板
    styles/                  tokens.css、element-plus.css、base.css；具体职责见 UI 规范
```

模块内文件直接放模块根目录，文件变多后再拆子目录；共享目录实际包含 `shared/http/`、`shared/components/` 和 `shared/utils/`，不预先建空目录。Vue 文件用 PascalCase，模块目录小写，composable 用 `useXxx.ts`。不创建只有转发作用的全量 `index.ts` 桶文件。

### 2.1 依赖方向

- `router` 引用页面，`layouts` 承载页面并使用组织切换等明确的公共业务入口；组件不能反向导入路由注册文件。
- 页面可以组合本模块组件和下表明确允许共享的组件。模块内部文件不读取另一个模块的页面状态，不通过导入兄弟 Page 来复用代码。
- 业务 `api.ts` 调用 `shared/http/client.ts`；传输层不引用 Pinia、Vue Router、Element Plus 或业务模块。`.vue` 组件中不直接写 Fetch。
- `stores` 可以调用账号／组织模块的 API，API 不能反向依赖 store。会话失效由应用边界协调清理，不能形成 client → store → api → client 的循环。
- `shared` 不导入 `features`。带组织成员、附件、文稿等业务含义的复用代码仍由对应模块拥有，不因为被两处使用就搬进 shared。
- 跨模块只导入明确对外的组件、函数及其类型，禁止读写对方私有状态。若互相导入，先由上层页面组合；不以事件总线隐藏循环。

| expense | M05 | ExpenseSection 维护费用、汇总、状态处理及凭证附件 |
| feedback | M07 数据访问 | 提供反馈资格、本人反馈与管理反馈接口；由 activity 的生命周期区块及公开详情消费 |

任务、报名、物资、附件与复盘是业务职责划分，当前不另建同名前端 features 目录；接口集中在 activity 的 p3.ts、registrations.ts、lifecycle.ts、publicActivity.ts。后端相应模块仍各自存在。

页面路由范围固定为账号入口、`/org/:orgId/...` 组织工作区、`/public/activities/:activityId` 公开活动以及 账号首页 `/` 中的本人公开参与记录；页签和外观遵循 UI 规范，实际开放范围由业务权限决定。

ActivityDetailPage 持有活动概要和权限上下文，以页签组合 ActivityP3Sections、RegistrationPanel、ExpenseSection 和 ActivityLifecyclePanel；区块只在对应权限／页签下读取所需数据。不能因详情可见就读取所有子资源。

## 四、先复用什么，什么时候封装

封装判断：是否存在同一条需保持一致的业务约束或已重复的状态逻辑？仅仅“都长得像表格”不构成封装理由。页面专用代码留在页面附近，两处实际复用且语义一致再提取；安全关键的统一传输和组织切换不必等复制两次才集中。

| 顺序 | 组件或逻辑 | 首次实现时的职责 | 明确不做 |
| --- | --- | --- | --- |
| P0／P1 | HTTP client、ApiError、会话清理 | 按开发规范集中传输与错误结构 | 不弹消息、不路由跳转、不偷偷重试写请求 |
| P1 | OrganizationSwitcher | 展示组织目录，发出目标组织选择；布局协调未保存提示和路由切换 | 不全局保存一个可被多标签页覆盖的“授权组织” |
| P2／P3 | 当前页面的 Element Plus Select＋organization 成员 API | 在当前组织选有效成员并提交成员 ID | 不预建 MemberSelect、全局缓存或任务创建逻辑 |
| P3／P5 | ActivityP3Sections／MyTasksPage／ExpenseSection 的附件区块 | 复用 activity/p3.ts 与 shared/http 的上传、下载、删除合同 | 不新增 attachment 目录或独立文件管理器 |
| 首次出现未保存编辑时 | 现有页面的 onBeforeRouteLeave／beforeunload 与 confirmDraftSave | 保护局部草稿、原资源与基准版本，卸载清理监听 | 不预建同名 composable，不自动持久化敏感草稿 |
| P8 | AiDraftPanel，归 ai | 接收生成所需上下文或回调，展示新结果及生成状态，发出采用草稿事件 | 不自主保存方案／总结，不自动替换人工内容 |
| 发生真实重复时 | 表单局部区段、列表查询逻辑、无业务含义的反馈展示 | 抽取共同字段或生命周期逻辑，保留页面差异 | 不设计几十个开关的万能组件 |

附件区块使用 Element Plus 的现有上传／文件选择 UI，经业务函数和 shared/http 提交 FormData；下载使用同一鉴权和错误处理并释放 Blob URL。页面不直连存储地址，不另写上传通道，见 [Element Plus Upload](https://element-plus.org/en-US/component/upload.html)。

视觉组合的建立时机和布局壳边界见 [UI 规范第六节](前端UI设计与规范.md#六组件使用与封装边界)。无业务表面才进入 shared，KPI、重点活动和AiDraftPanel等仍归各自模块；不得因统一外观集中业务状态。共享传输在 `shared/http/`；展示共享为 `shared/components/ListPage.vue`（列表页页头、筛选、面板、分页与"失败／首次加载／空态／刷新"四态），工具共享为 `shared/utils/` 的 token 读取和 `useLoadingSkeleton`（骨架 leading／trailing 延迟）。新增共享物先核对实际调用者，不按旧组件设想创建占位组件。

直接使用 Element Plus 的 Button、Input、Form、Table、Pagination、Dialog、MessageBox、Tag、Empty 和日期组件；不批量包装同名 BaseButton／BaseTable／BaseModal。状态文案用所属模块一份 typed 映射配合 Tag，不能把活动、报名、费用混为一个通用审批枚举。

纯函数放 utils，带 Vue 响应式状态或生命周期的复用逻辑用 composable；不要把普通格式化函数全部命名为 useXxx。每次调用 composable 的状态默认属于调用者，跨页面共享状态才进入 Pinia，参考 [Vue composable 说明](https://vuejs.org/guide/reusability/composables.html)。

## 五、状态与多组织边界

### 5.1 状态归属

- Pinia：当前账号／会话状态、本人组织目录；不缓存完整活动表、经费或 AI 草稿。
- URL：当前 orgId、activityId、分页和可分享的筛选条件。路由是当前页面组织的唯一来源；store 中如需组织摘要，必须按 orgId 索引而非第二份可写 currentOrgId。
- 页面：表单、弹窗、当前列表、选择项与 AI 新草稿。活动子页面可以通过 props 或局部上下文接收概要，不重复创建全局活动 store。
- API 响应：服务端拥有权限、状态可用动作、金额汇总及报名名额的最终决定。前端可展示 `allowedActions` 和进行友好校验，不能实现第二套批准规则。

### 5.2 请求竞争与切换

组织切换先提示未保存内容，再清空旧页面结果和权限、改变路由、验证目标组织并读取数据。所有读取绑定 orgId、activityId、请求序号和会话代次；迟到结果、旧 401／403 的页面副作用都须核对当前请求范围及会话。取消 Fetch 只是减少等待，序号检查仍需保留。账号登录页的 401 与受保护业务接口的 401 分别处理，细则见开发规范。

不把组织选择写入服务端会话作为授权依据，避免两个浏览器标签页互相切换访问范围。每个请求显式携带资源范围，后端重新校验。已提交写操作与原组织绑定，切页不能宣称回滚；结果未知时按开发规范查询／重试，不能以新组织上下文处理旧结果。

当前组织受到 403／404 或成员变更影响时，清理该组织已加载的受保护数据并刷新组织目录；不清空用户其他组织的合法身份。账号 401 才触发全局会话清理。浏览器已经显示的内容不能在无推送时保证瞬时消失，后端逐请求授权始终是保障。

当前组织切回核对由 `OrganizationLayout.vue` 监听 `visibilitychange`：可见且会话有效时，读取组织身份并强制刷新目录。子页按组织及角色设置 key，角色变化卸载旧管理数据和未保存表单；角色不变及读取失败保持子页，错误可手动重试。组织 404 不渲染子页，组织选择器仅显示有效目录中的选择，避免成员移除后留旧名称。请求序号及会话代次拒绝旧响应，卸载移除监听。

组织角色不变时的活动职责由 `ActivityDetailPage.vue` 切回重读：失去本人活动负责人职责且不是组织负责人时，清除管理草稿并按权限代次卸载子区域；403／404 清除活动数据，权限不变或网络失败保留内容，失败提供手动核对。`ActivityP3Sections.vue` 与 `MyTasksPage.vue` 同时重读任务／物资及本人任务，保留筛选和新建表单；已开资料弹窗绑定新读取的同 id 任务，上传入口按当前管理者／承担者权限显示。各组件卸载时移除监听并作废旧请求，不依靠即时推送。

会话清理由 `App.vue` 按会话代次卸载旧页面，未登录时不渲染受保护路由；`main.ts` 在 Vue 完成卸载后核对代次并引导登录，避免旧页面的草稿守卫挡住失效跳转。切回标签页的会话检查复用同一失效入口；网络失败不作失效处理，也不清除草稿。

## 六、前端请求与错误消费

传输入口显式支持 JSON、URLSearchParams、FormData、Blob 和无响应体，不把每个成功响应都调用 json()，也不手工设置 FormData 的 multipart 边界。依[开发规范](开发规范.md)设置 CSRF、请求身份与超时，检查 HTTP 状态和媒体类型。TypeScript 声明不能验证网络数据；对分页结构、状态值及当前组件依赖字段做必要运行时检查，不为简单接口搭建一套自定义 schema 引擎。

2026-10-04：正文解析、Blob 读取与失败 ProblemDetail 读取均处于同一超时／取消与异常映射范围，携带响应头 requestId；正文格式无效归传输错误，不伪装成明确业务拒绝。等待凭据后再次检查主动取消，取消后不发送写请求。`session.observeUnauthorized` 复用现有入口，仅对当前代次的 `CSRF_INVALID` 作废凭据，不清理会话或自动重发。

账号页首次组织目录与本人报名读取使用既有 `useLoadingSkeleton`，首次加载、空态与错误互斥；经费、P3与生命周期使用局部加载／错误／重试状态，矩阵结果与限制见审核报告。报名面板暴露局部草稿／提交状态给活动详情既有离开及 beforeunload 守卫，校验前锁定输入，失败保留内容；AI 面板将未采用人工改稿计入既有保护，可用状态读取失败提供“重新读取”。刷新检查只验证 beforeunload 取消标记，不承诺浏览器强制阻止离开。

页面表单校验只用于友好反馈；服务端返回字段错误时映射到具体输入。请求 client 不使用 Element Plus 消息组件，页面不再包装并重复弹同一错误。权限错误、状态冲突和网络结果未知分别处理，提交失败保留输入，主动取消读取不报错。

`AiConfigSection.vue` 以原 saving／testing／mutating 合成 busy，直接禁用现有 Element Plus 表单及动作按钮；保存、测试、启停及清密钥入口在忙碌时返回，避免交叉写入及回填覆盖新输入。保存从整表校验开始置 busy，所有结束路径由原 finally 释放；校验、冲突或失败后恢复编辑，不增加传输包装或全局状态。

关键写入的未知结果沿用原请求键和原内容核对，不能每次重试换键。执行记录的待核对意图保存在 `ActivityLifecyclePanel.vue` 局部状态，冻结类型与正文并提供“核对记录结果”；详情离开及浏览器关闭检查未保存、发送中和待核对状态。取消离开保留原意图，确认离开提示先核对列表；不将这些草稿写入持久存储。

组织创建同样由 `CreateOrganizationDialog.vue` 在局部保存原键及内容，未知结果冻结表单并按原端点核对；弹窗关闭、路由离开及浏览器关闭保护原意图，成功后清空并刷新目录。明确拒绝可重新编辑，会话代次变化不消费旧结果；不新增持久草稿或通用作业中心。

邀请接受由 `JoinByCodeDialog.vue` 局部保留 `pendingCode`，发送中禁改及离开，未知结果冻结原码并提供“核对加入结果”，复用现有接受幂等接口。取消关闭、后退及刷新可保留，明确拒绝后保留输入并恢复编辑；组件、弹窗与会话代次拒绝旧响应，原码不入持久存储。账号页创建／加入共用既有 `loadDirectory()`，刷新后再次核对组件存活和会话代次，避免已离开账号页的旧回调导航；不增加全局状态或传输包装。

`ActivityP3Sections.vue` 的公共 guard 与 `MyTasksPage.vue` 复用既有 `captureAction`／`isActionCurrent` 模式，绑定原资源、组件存活、路由及会话代次。任务取消与两类资料删除确认在打开时捕获上下文，离开或 A→B→A 后不发旧请求；写入返回后核对再清表单、读取或通知父页，任务资料读取还核对当前任务。

`ExpenseSection.vue` 沿用同一模式，公共 guard 固定组织、活动、组件存活、切换代次及会话代次；作废／更正全局确认在打开时捕获范围，失效不发请求，也不建立更正待核对内容。经费写入及凭证读取使用原资源，返回后再核对，迟到结果不清表单、回填票据、弹出超支说明或刷新新页。普通异常仍进入公共处理，旧 401 用发起时代次，不能清新登录；`NotificationsSection.vue` 两种已读动作也按原代次消费错误及刷新。复用现有局部状态，不增加全局作业状态或 HTTP 包装。

邀请创建由现有 `OrgMembersPage.vue` 局部保存原组织、设置及键；未知结果冻结输入，关闭与路由离开可保留，错误在弹窗内展示。原键核对只恢复邀请元数据，`code=null` 时明确提示无法再次显示明文，提供绑定该邀请 id 的撤销确认；撤销成功后才由用户手动重新生成。邀请码不写入持久存储，正常首次响应仍可复制。成员、邀请撤销和退出确认沿用该页 `guard`，核对组件存活、原组织切换代次和会话代次，旧确认失效后不发请求，迟到响应不刷新或导航新页面。

活动信息、方案及总结的草稿另保存其基准版本，权限核对等后台读取保留草稿时也保留旧版本。共用 `confirmDraftSave` 只在版本变化时要求明确选择；取消保留内容，继续保存绑定已核对版本，确认期间的进一步变更仍由后端 409 拒绝。总结未修改时同步服务端新内容，已修改时须先保存再确认；驳回版本固定在打开弹窗时，冲突就近显示并保留原因，重新打开前复核新方案。

Element Plus 全局确认框可跨路由存活。活动提交／撤回、删除和生命周期动作在打开时捕获活动范围、版本及会话代次，沿用页面 `guard` 检查原范围及组件存活状态；详情另核对权限代次，避免 A→B→A 的旧确认恢复有效。页面已离开或身份失效时，旧确认不发写请求，不能读取新路由参数决定写入对象。已发送请求不宣称回滚；旧响应的 401 使用发起时代次核对，不清理新登录。

报名的公开详情、内部面板和账号页沿同一原则保护本人取消及管理取消。内部面板和公开详情复用局部 guard，捕获原活动／组织、会话和切换范围；内部管理资格变化也使旧上下文失效，驳回弹窗绑定打开时的目标。申请校验后的写入、报名开关、审核、反馈和导出等异步结果先复核上下文，避免迟到结果刷新新活动或用新活动命名旧名单；卸载时使旧读取失效。账号取消在确认打开时登记会话与组件存活状态，不在确认后才登记。未引入通用动作框架或改变后端授权。

CSRF 获取与刷新由会话协调层单飞处理，HTTP client 只接收当前请求所需头部及信号，不反向调用 store。账号模块按开发规范发送表单编码登录；密码、恢复码和完整登录请求不进入日志、URL 或持久存储。开发联调代理与端口也以开发规范为准，不照搬 Demo 配置。

登录表单也从校验开始锁定原 submitting，禁止重复提交与等待期间路由离开，捕获原回跳路径。`session.login()` 在登录 API 的 finally 作废 CSRF；服务端可能已登录并轮换凭据、而页面仅收到错误，下一次写入仍会重新获取。复用原获取及会话代次，不自动重放，也不让普通凭据错误触发受保护请求的全局失效。注册 409／恢复及改密 401 的统一提示保留结果未知后的登录核对路径，不增加额外结果状态。

`session.logout()` 捕获发起代次，退出失败时作废 CSRF 并用现有 HTTP client 限时读取 me；明确当前 401 `AUTH_REQUIRED` 才清理，核对仍登录／失败则保留状态并交调用页提示重试。账号与组织壳只在确认 guest 后导航，公开壳原地更新账号；三个入口均接住错误，旧响应不改新会话。复用既有清理、代次与 Element Plus 提示，不增加退出结果存储或通用操作框架。

账号注册、恢复、改密和重签沿用各自 submitting，在校验前置锁，Element Plus 表单固定输入，失败／校验结束由 finally 解锁；账号两种安全写入以原状态合并互斥，返回前核对组件与会话。`RecoveryCodeDialog.vue` 接收现有 submitting，集中保护发放中及未确认保存的路由和 beforeunload，关闭入口无法绕过确认，确认更新后再通知父页导航。弹窗宽度复用已有 min 与 token 写法；5xx／传输失败就地说明结果未知，使用现有登录／重签恢复路径。没有新增作业状态、传输包装、凭据持久化或后端请求键。

金额展示遵守两位小数合同，前端不使用浮点数汇总正式支出；日期点与纯日期分别处理。下载和导出同样走受控路径，不能拼接存储地址或从客户端拼全量敏感名单。

## 七、AI 编辑与 UI 演示边界

当前正式页面和[UI 规范](前端UI设计与规范.md#前端开发以已确认正式界面为基础)是后续界面基线；Demo 只在追溯原始风格或正式页面未覆盖的交互时按需查看。本文的目录与模块边界约束实现方式，不构成另选模板或重新设计外观的理由。

活动方案由 ActivityDetailPage 保存；总结和取消说明由 ActivityLifecyclePanel 保存，均调用 activity 的既有业务端点。AiDraftPanel 只生成、放入编辑区及记录采用状态，用户仍需人工保存与确认。用户采用新草稿后仍是页面编辑状态，点击业务保存才提交，版本冲突时不能覆盖他人内容。生成完成不自动批准活动或确认总结。

`AiDraftPanel.vue` 的 pendingGeneration 先写入 ref，再捕获其响应式对象，身份比较使用同一个代理，避免首次成功被当作旧结果；未知结果仍保留原键只读核对。采用请求固定原 generation 对象，返回后比较当前对象及会话代次，旧响应不替换期间新生成的记录或人工编辑文本；重复采用发送中直接返回，其他生成仍按既有流程。只复用局部 ref 与会话状态，不增加请求包装或全局作业状态。

当前 `UI演示/` 仅验证黑白橙风格、响应式布局和基本交互，不连接后端、不实现真实权限与模型调用，也不代表上述业务能力已完成。演示使用 Vue、TypeScript、Vite、Element Plus、CSS、SVG 与按需引入的 GSAP，暂不需要路由和全局状态管理；正式业务工程仍按本文采用 Vue Router、Pinia 等既定能力。当前视觉与交互已获认可，正式约束统一维护在 UI 规范；演示的存量 CSS 尚未全部 token 化，不能直接当作符合规范的生产源码。GSAP 动画支持减少动态效果、组织切换与组件卸载清理，不依赖动画完成操作；未引入 Vue Bits 或图表平台。每日批准走势为可核对样例数据的视觉探索，正式统计接口仍按计划书与用户后续确认实施。

### 7.1 组织模型设置

组织模型设置路由为 `/org/:orgId/settings`，页面及 API 归 features/ai，组织导航仅承载入口。仅组织负责人加载完整配置 DTO；活动负责人只读取生成所需可用状态。密钥输入只留在表单局部内存，不进 Pinia、localStorage、URL 或日志；保存、离开或切换组织后清空，不从服务器取回旧密钥。协议、地址、模型、密钥与测试行为遵循计划书 7.4 和后端架构 6.4。

设置页“保存并生效”只发原PUT，由后端同事务启用，不串联测试／启用请求；连接测试仍为显式可选诊断，保留原键核对。工作台返回后重新读取模型状态；无草稿时OWNER入口携带`?create=1`进入活动列表，列表核对当前组织角色后打开既有创建表单并移除该参数，不自动提交。活动负责人无候选与无复盘活动时进入列表，普通成员不增加生成入口。

## 八、验证重点

创建工程后按开发规范运行类型、规范、测试和构建检查，UI 门禁按前端 UI 规范执行。除正常操作外，至少验证：组织切换慢响应、同一活动筛选竞态、旧会话响应不清除新登录、401 并发不重复跳转、403 不误清其他组织、上传 CSRF 与下载错误、204 响应、金额与纯日期格式、未保存离开、AI 采用草稿后人工保存及版本冲突。

这些是持续检查要求，实际结果见开发进度审核报告。跨组织访问、名额和金额一致性仍须由后端真实入口与数据库测试证明，前端组件测试不能单独代替。
